## 2. Semirings (`tannen.kernel.semiring`)

BRIEF P4: `Rel[K, S]` with S a commutative semiring — `ℤ` gives Z-sets and deltas, `𝔹`
gives sets, `Why` gives support-set provenance, and products compose. One mechanism,
two uses.

```
class Semiring(Protocol):
    name: str;  zero: A;  one: A
    def add(self, a: A, b: A) -> A
    def mul(self, a: A, b: A) -> A
    def encode(self, a: A) -> Value      # the canonical-encodable image of an annotation
```

`encode` exists because a `Rel`'s identity is the content address of its annotated
content (§3): an annotation that cannot be canonically encoded has no identity, so it is
not an annotation. Semiring equality is **by `name`**, never by object identity — a
product built twice must compare equal, and `name` is what the canonical form records.

Instances, with their `name` in parentheses:

- **`Z` (`"Z"`)** — `(ℤ, +, ×, 0, 1)`; `encode(n) = n`.
- **`B` (`"B"`)** — `({false, true}, ∨, ∧, false, true)`; `encode(b) = b`.
- **`Why` (`"Why"`)** — support sets. An element is a finite set of finite sets of refs in
  the pinned grammar [cites: provenance-ref-grammar]; `add` is union, `mul` is pairwise
  union, `zero` is `∅`, `one` is `{∅}`. Elements are **antichain-normalised**: after every
  operation any support set that is a strict superset of another in the same element is
  dropped. `Why.of(*support_sets)` is the constructor; an atom outside the ref grammar is
  refused by name. `encode(w)` is the list of its support sets, each sorted by code point,
  the outer list sorted by the canonical bytes of the inner.
- **`product(A, B)` (`"<A.name>*<B.name>"`)** — elements are 2-tuples, every operation
  componentwise; `encode((a, b)) = [A.encode(a), B.encode(b)]`.
- **`ZxWhy` (`"Z*Why"`)** — `product(Z, Why)`, and **the default** (§5.5, decision D0002).
- **`Z_ONLY`** — an alias of `Z`. It exists so that the opt-down BRIEF §5.5 names is
  spelled exactly as the brief spells it.

`SEMIRINGS` maps each name to its instance, and `Rel.from_value` consults it: a `Rel`
encoded under a semiring this build does not know is **refused by name**, never guessed at
(the door discipline [cites: exactness-and-the-door]).

### 2.1 `BagSemiring` — the extra structure `distinct`, `aggregate` and SQL need

Three of the eight operators are not definable over an arbitrary commutative semiring, and
saying so out loud is the whole of this subsection. `distinct` needs a notion of "one row
with the same support"; `aggregate` needs that plus a copy count; the bag image the L6
mapping is built on needs the copy count. A semiring that does not declare them cannot be
used with those operators, and is refused **by name at the call, not silently coerced**:

```
class BagSemiring(Semiring, Protocol):
    def multiplicity(self, a: A) -> int   # >= 0; the number of copies in the bag image
    def collapse(self, a: A) -> A         # "one row, same support"
```

- `Z.multiplicity(n) = n` and `Z.collapse(n) = 1 if n > 0 else 0`, **both raising
  `SemiringError` for `n < 0`**: a negative multiplicity has no bag or set image. Negative
  annotations cannot arise from M1's operators (§4.4), and defining their collapse is the
  delta executor's job at M3. Refusing is honest; guessing `1` would not be.
- `B.multiplicity(b) = 1 if b else 0`; `B.collapse(b) = b`.
- `Why.multiplicity(w) = 1 if w else 0`; `Why.collapse(w) = w` (`add` is already
  idempotent, so `Why` is its own collapse).
- `product(A, B).multiplicity((a, b)) = A.multiplicity(a) * B.multiplicity(b)` and
  `collapse` is componentwise. Everything about `ℤ × Why` follows from this rather than
  being special-cased: `(2, w)` has multiplicity 2, and `(0, w)` — a row with support but
  no surviving copies — has multiplicity `0 * 1 = 0` and is therefore absent from the bag
  image while remaining a stored row (§3).

`is_positive(a)` is `a != zero`, and is what `anti_join` tests. It needs no `BagSemiring`.

Axioms (law L1.1, L1.2): `add`/`mul` commutative and associative, `zero`/`one` their
identities, `mul` distributes over `add`, `zero` annihilates; `collapse` is idempotent,
`collapse(zero) == zero`, and `collapse(add(a, b)) == collapse(add(collapse(a),
collapse(b)))` — the weak form, because `collapse` is not additive (`collapse(1 + 1) = 1`
but `collapse(1) + collapse(1) = 2`).

## 3. `Rel` — the annotated relation (`tannen.kernel.rel`)

A `Rel` is a finite K-relation: a map from rows to annotations, with finite support.

- A **row** is a mapping from column name (`str`) to a value in the M0 encodable domain
  (`docs/specs/m0.md` §2). A **schema** is the sorted tuple of column names; it is
  non-empty and free of duplicates, and a column name that is not a `str` is refused by
  name. Every row in a `Rel` carries exactly the schema's columns; a ragged row is refused
  by name. (A columnless relation would be the unit of a product `Rel` does not have; when
  M3 needs one it arrives with a law rather than as an accident of the constructor.)
- **Row identity is the row's canonical encoding.** Two rows whose canonical bytes are
  equal are one row and their annotations `add` — so `Decimal("1.50")` and `Decimal("1.5")`
  merge, and NFD and NFC spellings merge, for free and by construction rather than by a
  rule anyone has to remember.
- **The schema carries names, not types.** A value type system is not in BRIEF §8's M1
  scope; the L6 fragment declares its own column types for the SQL mapping (§7) and
  nothing else needs them.
- **Zero annotations are absent, not stored.** A row supplied with the semiring's `zero`
  is dropped at construction, so a `Rel`'s identity is exactly its non-zero content.
  "Zero" means the semiring's `zero` and nothing else: under `ℤ × Why` the annotation
  `(0, {{r}})` is **not** zero and its row is retained. Privileging the ℤ component here
  would make `Rel` non-generic in its semiring, which is the one thing P4 is for.

### 3.1 Canonical form (`rel/1`) — pinned by golden hash

`Rel.to_value()` is the value below, and `Rel.content_address()` is its content address
[cites: pkm-event-identity]:

```json
{"tannen": "rel/1",
 "schema": ["<sorted column names>"],
 "semiring": "<semiring name>",
 "rows": [[<row>, <semiring.encode(annotation)>], ...]}
```

`rows` is sorted by the canonical bytes of each row. `Rel.from_value` inverts it.
`annotations_reason` (§3.2) is **not** in the canonical form: two Rels with the same
content are the same Rel whatever anyone wrote about their annotation choice.

The corpus `tests/laws/m1/golden-rels.json` fixes thirteen `(canonical bytes, address)`
pairs for this form — including the zero-drop, the decimal and NFC merges, the retained
`(0, {{r}})` row, and four operator results. It was computed by Session A against the M0
encoder and is the frozen oracle: **M1's kill criterion is a golden mismatch, and the
response is to fix the encoding before anything else lands** (§10).

### 3.2 Annotation defaults (BRIEF §5.5, decision D0002)

```
Rel(schema, rows=(), *, annotations=None, annotations_reason=None)
```

`annotations=None` means `ZxWhy`: every pipeline gets deltas *and* support-set provenance
without asking. Any other explicit choice — `Z_ONLY` included — **requires
`annotations_reason`**, and constructing without one raises `RelError`. BRIEF §5.5 says
the opt-down happens "with a recorded reason"; a required argument is what that sentence
means when it is mechanical rather than aspirational. Operators propagate the reason from
their inputs; only the public constructor demands it.

### 3.3 The bag image

`Rel.to_bag()` returns the list of row tuples (in schema order) with
`multiplicity(annotation)` copies of each, sorted. It raises `SemiringError` on a negative
multiplicity and `OperatorError` if the semiring is not a `BagSemiring`. This is the whole
of the L6 mapping's tannen half (§7).

## 4. The operators (`tannen.kernel.ops`)

Each operator ships a **type rule** and a **semiring rule**. The semiring rule *is* the
provenance rule whenever S carries a `Why` component, which is why there is not a separate
one: that is what P4's "incrementality and provenance as two instances of one mechanism"
buys. Delta rules arrive with the delta executor at M3 (BRIEF §8).

Every operator accepts `Rel` or `Outcome` inputs and returns an `Outcome` (§5).

| Operator | Semiring rule | Type rule |
|---|---|---|
| `select(rel, predicate)` | `(σ_p R)(t) = R(t)` if `p(t)` else `zero` | schema unchanged; `predicate` is a total row→bool |
| `project(rel, columns)` | `(π_C R)(t) = Σ_{t'|_C = t} R(t')` | `columns` non-empty, no duplicates, `⊆ schema`; out-schema `sorted(columns)` |
| `map_rows(rel, f, schema)` | `(map_f R)(u) = Σ_{f(t) = u} R(t)` | out-schema is **declared**, not inferred — an empty Rel still has one; a row of the wrong shape quarantines |
| `union(a, b)` | `(A ⊎ B)(t) = A(t) + B(t)` | identical schemas and identical semiring `name` |
| `join(a, b, on)` | `(A ⋈ B)(t) = Σ A(t_a) · B(t_b)` over pairs agreeing on `on` | `on` non-empty and `⊆` both schemas; the **non-`on` columns must be disjoint** — a clash is refused by name, never silently suffixed; out-schema is the sorted union, with one copy of each `on` column |
| `distinct(rel)` | `collapse(R(t))` | requires a `BagSemiring` |
| `anti_join(a, b, on)` | `R(t)` where no `b`-row agreeing on `on` has `is_positive` | `on` non-empty and `⊆` both schemas; out-schema is `a`'s |
| `aggregate(rel, by, monoid, value_of, into)` | see §4.1 | `by` **non-empty** and `⊆ schema`; `into ∉ by`; requires a `BagSemiring` and a `Monoid`; out-schema `sorted(by + [into])` |

Projection **sums**; it is the bag projection, not `SELECT DISTINCT`. Composing it with
`distinct` is how you spell the other one, and that composition is visible at the call site.

### 4.1 `aggregate`, and why `by` may not be empty

For each group of rows agreeing on `by`, the folded value is `monoid.fold` over
`value_of(row)` repeated `multiplicity(annotation)` times, **taken over the group's rows in
canonical-encoding order**. Fixing the order means a non-commutative monoid still gives a
deterministic answer, which is a better guarantee than requiring commutativity and hoping.
The output row is the group key plus `{into: folded}`, and its annotation is
`collapse(Σ group annotations)` — multiplicity one, support the union of the group's
supports, which is right for SQL and right for provenance at the same time.

`by` may not be empty. A global aggregate over a possibly-empty input is precisely where
SQL invents a NULL (`SELECT SUM(x) FROM t` on an empty table returns one NULL row, where
tannen would return no rows), and BRIEF P7 says there are no NULLs. Refusing the shape is
cheaper than mapping a divergence nobody wants. Global aggregates return when there is
something to say about the empty case.

### 4.2 Algebraic identities (law L1.8)

`union` commutative and associative with the empty Rel of the same schema as identity;
`join` associative and commutative up to schema; filter fusion `σ_p ∘ σ_q ≡ σ_{p∧q}`;
project composition `π_C ∘ π_D ≡ π_C` for `C ⊆ D`; `distinct` idempotent; `join`
distributes over `union`; `anti_join(R, ∅) ≡ R`; `aggregate` equals the direct fold.

### 4.3 Declared algebra (`tannen.kernel.algebra`, BRIEF §5.6)

```
Monoid(name, op, identity, witnesses)
AbelianGroup(name, op, identity, inverse, witnesses)
```

Construction checks associativity and the identity law (and, for `AbelianGroup`,
commutativity and inverses) over every triple drawn from `witnesses`, raising
`AlgebraError` by name. **An aggregate with untested algebra cannot be constructed**, which
is §5.6's sentence made mechanical. `witnesses` is a required, non-empty, finite tuple:
the caller supplies the evidence rather than the kernel guessing a generator, and the
check needs no Hypothesis at run time — Hypothesis is a dev dependency and registration is
not a test.

No standard-monoid library ships at M1. A monoid is four arguments; a stdlib of them
would be API surface with no law of its own.

### 4.4 The non-negative cone (law L1.9)

Every operator above maps non-negative-ℤ inputs to non-negative-ℤ outputs. Subtraction is
not in M1's surface, so a negative annotation cannot arise, so `to_bag` and `collapse`
never meet the case they refuse (§2.1). This is stated as a law rather than as a comfort:
when M3 adds subtraction it will break, loudly, in exactly the right place.

## 5. Quarantine (`tannen.kernel.outcome`, BRIEF P3, §5.4)

```
Outcome = Ok(rel: Rel, quarantined: Rel, operators: frozenset[str])
        | Quarantine(reason: str, detail: str, provenance: tuple[str, ...], operators: frozenset[str])
```

- **Row-wise failures quarantine the row.** An `Exception` raised by `predicate`, `f` or
  `value_of` puts that row into `quarantined` and leaves the rest processed. The lazy path
  — just `raise` — is thereby the correct path (§5.4).
- **`operators` is the set of operator names that contributed**, unioned from the inputs'
  outcomes plus the operator's own name. It is ordinary data on the value, not a global
  counter, so the kernel stays pure — and it is what makes the layer check of §6 sound.
- **`quarantined` is a `Rel`** over the same semiring, schema
  `("detail", "operator", "reason", "row")`, each row annotated `one`. `row` is the
  offending input row, so its provenance is its own content address; the node's descriptor
  travels in the derivation record, not in every quarantine row.
- **Whole-node failures give `Quarantine`.** A `Quarantine` input propagates: an operator
  given one returns a `Quarantine` naming it, and never touches its own inputs.
- **Empty is not quarantine.** A transform that raises on *every* row yields `Ok` with an
  empty `rel` and a full `quarantined` — "empty" is a declared, distinguishable outcome
  (P3), not a failure.
- **`BaseException` is not caught.** `KeyboardInterrupt` and `SystemExit` cross the node
  boundary untouched; wrapping them would make the process unkillable inside a transform.
- `Ok.unwrap()` returns the `Rel`; `Quarantine.unwrap()` raises `QuarantineError`.

## 6. Layers (`tannen.kernel.layers`, BRIEF P8, §5.9)

The four layers form a **chain** under operator-set inclusion, so "the most restrictive
layer admitting these operators" is well defined rather than a choice between incomparable
options:

| Layer | Admits |
|---|---|
| `capture` | nothing — oracles only (M4) |
| `serve` | `project`, `select` |
| `decode` | `project`, `select`, `map_rows` |
| `derive` | all eight |

`layer_of(operators)` is the least layer admitting them all — "a node's layer defaults to
the most restrictive admitting its operators" (§5.9). `check_layer(declared, operators)`
accepts a declaration at or wider than that and **raises `LayerError` on one that is
narrower**: a node may promise less power than it has, never more restraint than it
practises. The `serve` default for exports arrives with the export surface at M4; M1 has no
export.

**The operator set comes from the run, not from a parser** (D0083). Every `Outcome` carries
`operators` (§5), so `layer_of(outcome.operators)` is what the node actually did.
`@transform(layer=…)` is an optional *declaration*, defaulting to `None` = infer; the
executor computes `Built.layer = layer_of(outcome.operators)` and refuses a declaration
narrower than it.

A static scan of the decorated function's AST was the obvious alternative and is **wrong in
the unsafe direction**: an operator reached through `getattr`, an alias, or a helper the
scan does not follow yields a *narrower* inferred layer than the truth — a node claiming
more restraint than it practises, which is precisely the failure the check exists to
prevent. A static check that fails open is worse than a runtime one that fails closed, so
BRIEF P8's "membership is statically checked" is honoured by carrying the membership *in
the value* rather than by parsing for it.

## 7. The float door (`tannen.kernel.lossy`, BRIEF §5.8, P7)

`docs/specs/m0.md` §2 promised this arrives with the Rel layer; here it is.

```
Lossy(grid: Decimal)          # grid must be finite and > 0, else LossyError
lossy(value: float) -> Decimal
```

A `Lossy` maps a finite float to the nearest integer multiple of its grid, ties to the
**even** multiple, and returns that multiple as an exact `Decimal` — which the M0 encoder
already knows how to canonicalise. `NaN`, `±Infinity`, non-floats, and a grid that is not a
finite positive `Decimal` are refused by name (an `int` or `str` grid included: silent
coercion is the thing a door exists to prevent).

Two things about *how* are pinned, because both have a plausible wrong answer (D0085):

- **The rounding is over exact rationals**, never through a rounded intermediate. A float
  *is* its binary value: `1.005` is `1.00499…`, so on a `0.01` grid it goes to `1.00`.
  Routing it through `repr` first — getting `1.02` — would be a second, hidden lossy step
  inside the one construct whose entire job is to make loss explicit. This also rules out
  `Decimal.quantize`, which rounds to an *exponent* and therefore cannot express a grid
  like `0.25`, and rules out dividing in the ambient decimal context, whose 28-digit
  default precision would silently round the quotient (the trap `tannen.kernel.encoding`
  already met with `Decimal.normalize`).
- **The grid is a multiple, not a decimal place.** `Lossy(Decimal("0.25"))` is legal and
  means quarters.

A `Lossy` is **not itself an encodable value** — `encode_canonical(Lossy(...))` still
raises; what enters a `Rel` is its exact output. `Lossy.to_value()` gives
`{"grid": <the grid as a Decimal>}`, canonically `{"grid":{"$decimal":"<grid>"}}`, so a
transform's `params_hash` prices the grid — which is what "priced and visible" means.

No float is admissible in a `Rel` without going through it. That is not a new rule — it is
M0's encoder, unchanged.

## 8. Derivations and the reference executor

- `derivation_id(transform_descriptor, input_ids)` = the content address of
  `{"inputs": sorted(input_ids), "transform": transform_descriptor}`. Order-insensitive in
  the inputs, and every component is a ref in the pinned grammar.
- `@transform(kind=..., params=..., layer=None)` (`tannen.transform`) is **the only way** to
  put a function in a graph (§5.1). It computes `code_hash` as the ref of the decorated
  function's source — `inspect.getsource`, dedented, LF-normalised, decorator lines
  included — and `params_hash` as the content address of `params`; it derives the label as
  M0's `derive_label(fn.__module__, fn.__name__, seq)` where `seq` is the count of
  previously registered descriptors for that `(module, name)` pair; and it attaches
  `descriptor_id`, `label`, `code_hash`, `params_hash` and the optional declared `layer`.
  A lambda cannot be registered (`<lambda>` is not a name that derives a label), and
  registering the same function twice is refused rather than silently shadowing the first.
  An unregistered function handed to the
  executor is refused by name. Hashing the source means a comment change mints a new
  descriptor and invalidates that transform's evidence — deliberately: "what would make
  this a different event belongs in the hash" [cites: pkm-event-identity], and a rule with
  an exception for comments is a rule someone has to remember.
- `Node(transform, inputs)` where `inputs` are store refs of `Rel` values;
  `node.derivation_id` follows.
- `Built.layer` is `layer_of(outcome.operators)` — the most restrictive layer admitting
  what the node actually did (§6). A `transform` declaring a narrower layer raises
  `LayerError` here, at the one place that knows what ran.
- `TraceStore(root)` records `derivation_id → output_ref`, append-only. Re-recording the
  same mapping is a no-op; recording a **different** output for the same derivation raises
  `TraceIntegrityError` — one derivation, one output, by construction.
- `AlwaysRebuild` recomputes and records. `VerifyingTrace` consults the trace first; on a
  hit it verifies that the recorded output resolves in the store and that the store's
  verify-on-read passes, and **raises `TraceIntegrityError` if it does not**. A recorded
  output that has gone missing or been altered is not a cache miss: the store is
  append-only and write-once, so its absence means something happened outside the store's
  contract, and quietly rebuilding would erase the only evidence of it.
- A node that yields `Quarantine` writes **no** trace entry. A quarantine is a report about
  a run, not a cached result.
- `tannen.laws.harness.harness_subject(root)` widens the law descriptor's `params_hash`
  subject to cover the root `conftest.py`, `pyproject.toml`, and **every** file under
  `src/tannen` rather than only `*.py`; `implementation_subject` delegates to it. This
  closes red-team finding RT-09 (`docs/redteam/2026-08-24-m0-boundary.md`), which the M0
  boundary deferred to the start of M1 because landing it moves every descriptor by design
  — all M0 evidence is invalidated on the commit that lands it and is re-earned by the
  next run. Doing it first, before any M1 evidence exists, is why it is here and not later.

### 8.1 The Governor seam at M1 — the wire schema is OUT (D0088)

BRIEF §7 calls `VerifyingTrace` "a degenerate governor whose prior is a dirty bit", so the
seam's *implementer* arrives here. Its **Grade-S wire schema and frozen vectors do not.**

This is a timing call, and it is owed because nothing in-repo had made it: CLAUDE.md's hard
rule permits the artifact — "Never implement the Governor (§7) — the seam and its Grade-S
wire schema only" — BRIEF §8 does not schedule it, §8's post-M5 seam list mentions only the
governor *implementation*, and the only scheduling language anywhere is
`concepts/derive-decide-split.yaml`, which says "at M-later". The call: **M4 at the
earliest**, for three reasons in decreasing order of force.

1. **Two of the wire's four Request fields cannot be populated by anything at M1.** §7's
   Request is *(derivation graph summary, cost model, evidence records, demand)*. The graph
   summary exists here and evidence records shipped at M0; the **cost model**'s oracle-spend
   term arrives with SpendGuard at M4, and **demand** is an M5 notion. A Grade-S artifact is
   a schema *plus a frozen corpus of positive and negative vectors*, and adopters conform
   against the vectors. Vectors for fields nothing can produce would teach a shape that has
   never been executed — the wire-first rule (§2.1) read backwards.
2. **§7 itself:** "the governor is premature until demand logs exist — tannen ships the
   seam, the evidence stream, and nothing else."
3. **Nothing crosses a repo boundary at M1**, so §2.1's wire-first rule is not yet forcing;
   external bytes are a Tier-C door regardless.

Not a mechanism problem, and this document does not pretend otherwise: the route is paved.
The wire is tannen-owned, so it would follow the evidence record's precedent (D0033)
exactly — schema under `governance/schemas/`, vectors under the sealed `tests/laws/`, one
law, one decision record, **no new concept record**, and *not* under `conformance/vectors/`,
which is reserved for concept-record-cited corpora.

What M1 does do, to keep the deferral cheap: `Node` and `Built` (§8) expose exactly the
M1-available subset of those four Request fields — descriptors, inputs, and the staleness
`VerifyingTrace` computes — so when the schema lands it is a projection of data that
already exists rather than a new shape.

## 10. L6 — the differential law, and M1's kill criterion

**The SQL-expressible fragment.** Not every operator has a SQL image and the ones that do
not are named rather than approximated: `map_rows` is excluded (an arbitrary Python
function has no SQL image). The fragment is `select`, `project`, `union`, `join`,
`distinct`, `anti_join`, and `aggregate` over the two monoids below.

**The value domain**, deliberately narrower than tannen's:

| Column type | tannen | DuckDB | Excluded because |
|---|---|---|---|
| int | `int` in `[-2³¹, 2³¹)` | `BIGINT NOT NULL` | unbounded ints overflow `BIGINT`; the bound also keeps `SUM` inside `HUGEINT` |
| text | `str`, NFC, short, small alphabet | `VARCHAR NOT NULL` | long or exotic strings buy collation and normalisation divergence, not coverage |
| bool | `bool` | `BOOLEAN NOT NULL` | — |

`Decimal` is excluded: DuckDB's `DECIMAL` has a precision ceiling tannen's does not, so the
fragment would be testing that ceiling. `None` is excluded because it is the image of
`Option.none` and SQL would read it as NULL. Nested values are excluded because they have
no column image. Each exclusion is a place tannen is *wider* than SQL, not a place it is
weaker, and each is stated so that a future widening is a decision rather than a surprise.

**The no-NULL mapping**, in full (BRIEF §6 requires it explicit):

- A `Rel` becomes a table of `NOT NULL` columns holding `multiplicity(a)` copies of each
  row — `to_bag`. Every column is `NOT NULL`, so no operand of any comparison below is
  ever NULL and SQL's three-valued logic never engages.
- `select` → `WHERE`, over the closed predicate grammar `col {=,<>,<,>} literal` combined
  with `AND`, `OR`, `NOT`.
- `project` → `SELECT cols` — no `DISTINCT`, because projection sums.
- `union` → `UNION ALL`.
- `join` → `INNER JOIN ... USING (on...)`, whose single copy of each join column is
  exactly the out-schema of §4.
- `distinct` → `SELECT DISTINCT`.
- `anti_join` → `WHERE NOT EXISTS (SELECT 1 FROM b WHERE b.k = a.k AND ...)`.
- `aggregate` → `SELECT by..., SUM(v) AS into FROM t GROUP BY by...` with `by` non-empty,
  so an empty input gives zero rows on both sides and no NULL is generated. The two
  monoids in the fragment are sum-over-int and count (`value_of = 1`); both are commutative
  and associative, so the canonical-order fold of §4.1 and SQL's unspecified order agree.
- Results are compared **as multisets** of row tuples in sorted-schema order. SQL results
  are unordered and nothing here pretends otherwise.
- `SET threads TO 1` on the connection. Integer sums are order-independent so this changes
  no answer; it removes a source of run-to-run variation from the oracle, which is what the
  kill criterion is about.
- The law runs the same generated graph under **both** `Z_ONLY` and the default `ZxWhy`,
  asserting the same bag image. The Why component must be inert on the data: provenance
  that changed the answer would not be provenance.

**Kill criterion (BRIEF §8, applied to M1): a flaky L6 is an encoding defect, and the
encoding is fixed before anything else lands.** "Flaky" includes any L6 failure that does
not reproduce under the derandomised profile: the response is never to loosen the
comparison, re-seed, or narrow the generator — it is to find what the canonical form or the
mapping gets wrong. The golden corpus (§3.1) exists so that this failure has somewhere
smaller to be found than a random graph.

`tests/laws/m1/_fragment.py` is frozen with them (D0089). It holds the L6 fragment's
expression **catalogue** — 22 named shapes, each a plan plus the SQL it must agree with —
its data generators, and its plan interpreter: the oracle's half of L1.16, frozen for the
same reason the assertions are, because an oracle Session B can edit is not an oracle. A
fixed catalogue rather than a recursive expression generator is deliberate: a generator bug
in a frozen file can only be *superseded*, never fixed, and the catalogue's shapes were each
executed against DuckDB before the freeze. Composition depth is bought by making shapes
composite (`join` → `project`, `distinct` → `join`, `aggregate` → `distinct`) rather than by
generating trees; the randomness lives in the data, where it costs nothing to be wrong.

It imports nothing from tannen — the law module passes `ops` and the monoids in — so it can
never be the reason a pre-implementation run *errors* instead of *skipping*.

`tests/laws/m1` is a **sealed** directory (`governance/tier-c.yaml`, decision D0056): every
file under it carries a manifest row, so Session B can add neither a `conftest.py` nor a
helper module there. Everything shared is frozen here or does not exist.

Law files guard their tannen imports with `pytest.importorskip`, so pre-implementation they
are visible skips, never false greens.

## 12. Completion

M1 is done when:

- `uv run pytest tests/laws/m1` is green with **zero skips**;
- `uv run tannen laws report` shows fresh evidence for L1.1–L1.17 — after L1.17 lands,
  since it moves every descriptor;
- `make verify` is green, including `lint-imports` proving the kernel still imports no IO,
  no clock, and no `duckdb`;
- the M1-close digest is generated.

Session B runs in the milestone worktree (`~/git/worktrees/tannen/m1`), in a fresh session,
and never edits a frozen path. If a frozen law here turns out to be wrong, it is not
edited: the defect gets a decision record, the correction gets a new frozen file, and the
old one is marked superseded in the manifest notes (CLAUDE.md). The record of the mistake
is part of the record.
