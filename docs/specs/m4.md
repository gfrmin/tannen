### 0.1 Prior art, pinned

WARC (ISO 28500) for the Fetch envelope's shape — BRIEF §11 names it — taken as far as
M4 needs: a request record and a response record, headers as ordered pairs that may
repeat, the payload by digest. S3's conditional write (`If-None-Match: *`, which R2
honours) for write-once on a remote store. Both are third-party prior art, not registry
concepts, so neither carries a `[cites: …]` marker (m1 §0.1's reason).

## 1. Package layout, and the surface Session B implements

Everything M4 adds is **shell**, outside `tannen.kernel`: the kernel's `kernel-no-io` and
`kernel-no-clock` contracts are unchanged and nothing here weakens them. The frozen adapter
`tests/laws/m4/_boundary_subject.py` and every M4 law file are written against exactly the
names below (the L3.15-docstring precedent); a name not listed is implementation freedom.

**`tannen.oracles`** (new; BRIEF §5.3's only IO doorway):

- `Fetch(name, *, reproducibility=None, transport, method, headers, unit, price)`,
  `LLM(name, *, reproducibility=None, transport, model, prompt, tool_schema, params, unit,
  input_price, output_price)`, `Clock(name, *, reproducibility=None, transport, unit, price)`
  — each with `.kind`, `.name`, `.reproducibility`, `.descriptor`. `params` is a canonical
  value carrying at least an integer `max_tokens`. `reproducibility` defaults to `None` only
  so that omitting it raises `UndeclaredReproducibility` rather than a `TypeError`.
- `CLASSES` — the declared reproducibility classes, `("bit", "in-distribution",
  "non-reproducible")`: pkm's vocabulary [cites: pkm-determinism], in the spellings
  docs/specs/m0.md §4 already fixed.
- `input_key(request) -> ref`: the content address of the invocation's variable part —
  Fetch `{"uri"}`, LLM `{"messages"}`, Clock `{"label"}`.
- a **transport** is any callable `transport(effective_request) -> response`. The
  effective request is what §3 records verbatim. The response is, for Fetch, `{"status",
  "headers", "body": bytes, "observed_at"}`; for the LLM, `{"resolved_model", "content",
  "usage": {"input_tokens", "output_tokens"}}`; for the Clock, `{"instant"}`. Real
  transports ship in this package; no law invokes one.
- `REPLAY`, `SPEND`; `load_budget(mapping | path)`; `Oracles(store, *, mode=REPLAY,
  budget=None)` with `.invoke(oracle, request) -> capture ref` and `.read(ref) -> response`
  (a Fetch body read back as bytes).
- refusals by name: `NovelInvocationRefused`, `SpendDenied`, `CaptureWriteFailed`,
  `UndeclaredReproducibility`, `CaptureConflict`.

**`tannen.store`** (changed): `Store(root)` keeps its meaning — every frozen M0–M3 law
constructs a store that way — and is `Store(backend=LocalBackend(root))`; a store is built
from exactly one of the two. `R2Backend(client)` speaks an **`ObjectClient`**:
`put_if_absent(key, data) -> bool` (True if it created the object, False if one was already
there, which it leaves untouched), `get(key) -> bytes | None`, `list(prefix) -> sorted keys`.
A ref's key is `objects/<hex[:2]>/<hex[2:]>`. `IntegrityError`, `MissingRef` and
`GC_REFUSAL` are unchanged. **`tannen.r2`** (new) is the real R2 client implementing
`ObjectClient`; no law instantiates it (§5).

**`tannen.export`** (new): `export(store, built) -> bytes` — a `Built` whose layer is
`Layer.SERVE`, emitted as its output's bytes; anything else raises `LayerError` (§7).

**`tannen.cli`** (changed): `tannen run MODULE:CALLABLE --store PATH [--budget PATH]
[--spend]` imports `MODULE`, opens `Oracles(Store(PATH), mode=SPEND if --spend else REPLAY,
budget=load_budget(--budget))` and calls `CALLABLE(oracles)`. Exit 0 when it returns; exit
1 when it raises `NovelInvocationRefused`, `SpendDenied`, `CaptureWriteFailed` or
`CaptureConflict`, with the exception's class name on stderr.

**`tannen.incremental`** (changed, the carry-forward): public `binary_operators()` — the
delta operators whose nodes take two inputs, derived from the package's own arity table,
never listed — and `required_params(operator)`, the parameters a node of that operator must
declare; plus the RT-M3-01 and RT-M3-03 remedies of §8.

## 2. Oracle identity (`oracle/1`) [owns]

An oracle's descriptor is the content address of `{"tannen": "oracle/1", kind, name, the
full effective spec, the declared reproducibility class}`. The effective spec is every
field that decides what the world is asked and what it costs — for the LLM the model id,
the prompt, the tool schema, the params and the prices; for Fetch the method, the fixed
headers and the price; for the Clock its price — so no two different questions share one
recorded answer. The class is declared per oracle, is part of the identity, and is data the
kernel carries and never interprets: "do not redefine, do not fix" [cites: pkm-determinism].
An oracle with no class from `CLASSES` cannot be built. Constructing an oracle touches
nothing. L4.1.

## 3. Captures (`capture/1`) [owns]

**Invoke iff no capture** (BRIEF §4). A capture answers the pair `(oracle descriptor, input
key)`; if one exists the invocation returns it and the transport is not reached, in any
mode, at any budget, in any session over the same store [cites: pkm-event-identity]. A hit
costs nothing and needs no budget headroom. Two captures answering one pair — which two
racing processes can produce and a sequential caller cannot — is `CaptureConflict`: nothing
can say which is the record, and choosing one silently would be a guess. L4.3.

**Capture before read** (BRIEF P1). A novel invocation writes a reservation (§4), calls the
transport, writes any payload blob and then the capture, and only then returns the
capture's ref; `read` returns what that capture, read back and verified, says. If the
reservation cannot be written nothing is called; if the capture cannot be written after
the call the value is withheld; both are `CaptureWriteFailed`. A capture altered behind the
store's back is refused on read (`IntegrityError`), never served from a copy in memory.
L4.2.

**The envelope.** A capture is:

```json
{"tannen": "capture/1", "kind": "fetch|llm|clock", "oracle": "<descriptor>",
 "input_key": "<ref>", "request": {…}, "response": {…},
 "scope": "<budget scope>", "unit": "<money unit>", "price": <int>, "reservation": "<ref>"}
```

`request` is the effective request exactly as handed to the transport. `response` is: Fetch
`{"status", "headers" (ordered [name, value] pairs, repeats kept, as WARC keeps them),
"body" (the ref of the payload bytes — never inline), "observed_at"}`; LLM
`{"resolved_model" (recorded, never normalised to the requested id), "content", "usage"}`;
Clock `{"instant"}`. Instants are RFC 3339 UTC with a `Z`. `price` is the settled cost in
`unit`: the declared price for Fetch and the Clock, the provider's reported usage times the
declared prices for the LLM. All money is an integer; nothing in a capture is a float
[cites: exactness-and-the-door]. Every ref is in the pinned grammar
[cites: provenance-ref-grammar]. The schema is `tests/laws/m4/capture/schema.json`, frozen
with a positive and a negative vector corpus beside it — Grade S, parse-all-positives /
reject-all-negatives, the evidence-record shape (L0.10) one milestone on. It lives under the
sealed `tests/laws/` rather than `governance/schemas/` because the latter is custody-set
(D0088's route otherwise). L4.6, L4.7.

**The Clock.** Time is an oracle (BRIEF P7, §5.7): a reading is a capture keyed by a label
the caller names, so "the time at label X" is a replayable question with one recorded
answer, and a new label is a new reading that replay-only refuses. L4.8.

## 4. Modes and SpendGuard

**Replay-only is the default** (BRIEF §5.10). `Oracles(store)` and `tannen run` without
`--spend` refuse every novel invocation by name, **before** the transport is touched, and
write nothing; a refusal issued after the call has already spent. `SPEND` / `--spend` is
the only spelling that can reach a transport, and it engages SpendGuard. L4.4.

**The budget file.** `load_budget` reads a mapping with a top-level `scope` (the spend
period a capture is charged to — a milestone), a `unit` (the exact money unit every price
is an integer count of) and `ceilings` (an integer per oracle kind and a `total`). Ceilings
stay YAML integers because the one other consumer of `budget.yaml`'s schema,
`scripts/check_manifest.py`, compares each ceiling to the policy envelopes numerically and
is custody-set. A budget that names no scope or no unit authorises nothing; `budget.yaml`
as frozen at M0 names neither, so it refuses everything until an owner sitting gives it a
scope, a unit and a nonzero ceiling (Tier-C door 1).

**Admission** (default-deny, BRIEF §4). A novel invocation is admitted iff the budget names
a ceiling for the oracle's kind and for the total, the oracle's `unit` is the budget's, and
for **both** ceilings `ceiling > 0 and spent + worst_case <= ceiling`. So **a zero ceiling
refuses even a zero-priced call** — the plain inequality would admit it, and `budget.yaml`
has promised since the opening that with ceilings at zero `--spend` can authorise nothing.
A consequence worth stating: a novel Clock read under `--spend` needs a nonzero clock
ceiling, and so an owner-signed envelope. `worst_case` is exact and known before the call:
the declared price for Fetch and the Clock; for the LLM, `input_price` times the UTF-8 byte
length of the canonical effective request (a token is at least a byte) plus `output_price`
times `max_tokens`.

**Spend is a fold over the store, never a counter.** Before the call a `reservation/1`
value — `{kind, oracle, input_key, scope, unit, worst_case, attempt}` — is written, and the
capture that follows names it. `spent` for a scope (per kind, and in total) is the sum over
that scope's reservations of the settled price of the capture that names it, or, if none
does, the reservation's worst case. So a second session over the same store cannot start
again from zero, and a paid call whose capture failed to write still counts. A world that
overruns its declared worst case — an LLM reporting more usage than the bound allowed — is
recorded as reported, never clamped, and the next admission sees it. L4.5.

## 5. The R2 backend

A store over an `ObjectClient` answers exactly as the local store does: the same ref for
the same bytes, the same bytes back, the same enumeration, the same `MissingRef` and the
same `gc` refusal. **Write-once** is kept by `put_if_absent`, which never replaces an
object; **integrity** is kept by verifying every read, because the remote is not trusted
to return what it was given (BRIEF §10: no store mutation, ever; the M0 rule that integrity
is verification). L4.11.

**What is not claimed.** That any real client conforms to R2. The law drives a frozen
in-memory client with S3's conditional-write semantics. The first write to a real bucket
is a network write outside a captured oracle — `governance/policy.yaml` says
`network_writes: captured-oracles-only` — so it is Tier-C door 2 and is queued for the
owner (D0228), together with where the evidence stream's "durable home" actually lives.

## 6. The doorway: no hidden IO in the shell

BRIEF §5.3's kernel half is a guard already. Its shell half was prose: nothing stopped
`tannen.store`, `tannen.executor` or `tannen.incremental` from importing a socket or a
clock. L4.9 freezes it: outside `tannen.oracles`, no `tannen` module imports a network
module, except `tannen.r2` (a store transport, not a way to read the world); and outside
`tannen.oracles`, no `tannen` module imports a clock module, except `tannen.laws` (whose
`run_at` is the runner's time, per the evidence schema, never the kernel's). The clock set is
**derived** from `governance/importlinter.toml`'s `kernel-no-clock` contract. The network
set is **named in the law as residue**, because `kernel-no-io` also lists `os`, `pathlib`,
`tempfile` and `io`, which the shell legitimately imports. A static scan cannot see
`importlib.import_module` or `__import__`, and the law says so rather than claiming it. The
matching import-linter contract belongs in a custody-set file and is queued (D0229); the
frozen law enforces from Session B either way.

## 7. Layers, and the export

An oracle invocation is the capture layer (BRIEF P8): `capture` still admits no operator
(L1.10 unchanged), and the only way anything downstream reads what the world said is a
capture's ref. `export(store, built)` admits a `Built` whose layer is `Layer.SERVE` —
project and select only, so its provenance is trivially that of what it projects — and
emits exactly that node's output bytes, the same every time; a node that ran anything wider
is `LayerError`. That is m1 §6's promise kept. ClickHouse emission is out (scope). L4.10.

## 8. The M3 carry-forward

**The binding.** The three red teams to date each found the same hazard (RT-M1-01,
RT-M2-01, RT-M3-04): a frozen law file that says `import _delta_model` receives whatever
module holds that name. `docs/proposals/2026-09-04-m3-boundary-sitting/SUPERSESSIONS.md`
measured the recommended package-qualified import and refuted it, and measured the fix: load
the frozen bytes by file location. `tests/laws/m4/_frozen_bind.py` is that loader, frozen
here, with two rules — never read `sys.modules` before loading; never leave a bare stem
behind (M3's names are borrowed for the load and restored, M4's helpers live under a private
dotted name). **No M4 law file binds anything by a bare import**, and a structural ratchet
in `tests/test_laws_runner.py` keeps it so for every later milestone.

**The nine successors.** Each frozen M3 law file is superseded forward by one M4 file that
restates its claim and binds its oracle from the bytes (D0106 ruling 2). The M3 files are
retained unedited and keep running — the poison fixtures name them. Successors take **L4**
ids, because the evidence plugin keys a run by law id alone and a second `L3.x` definition
under `m4/` would merge into M3's own run and strip it of its record; D0128's successor of
L1.5 was likewise L2.2. No `governance/laws.yaml` entry is made: a `superseded:` entry is a
strict xfail, and the M3 nodes still pass.

**RT-M3-05, answered.** *Is a law that shares its node with three others a law or a
clause?* A law is the unit a frozen check can falsify on its own; rows that share their
only node are clauses of the law that node attests. M3's five bundles are each one frozen
check (`_delta_model.py`'s `check_delta_algebra`, `check_integrated_ops`,
`check_convergence`, `check_graph_convergence`, `check_doors`), so each bundle's successor is
ONE law with the bundle's rows as its clauses, and one evidence record says so honestly.
Splitting them instead would mean re-authoring M3's checks as new frozen code — the place
D0203's refutation stage found false claims enter. And for M4's own laws: **no node claims
more than one law**, every law has at least one node of its own, enforced for every
milestone after m3 by `tests/test_laws_runner.py`.

**The kill criterion moves with its law.** m3 §11 made a failure of L3.12 M3's kill
criterion. Its successor is L4.19 (L3.11 and L3.12 as clauses), and the criterion reads on
L4.19 now — bound from its bytes, so it cannot be answered by a decoy.

**L3.15, corrected.** L4.21 restates what is true (docs/specs/m3-corrections.md): a default
replay recomputes and writes nothing new, `rebuilt` is a store measurement, a recorded step
is served from the trace, a tampered trace raises. It does **not** carry the L3.15 row's "a
quarantining step moves nothing": no L3.15 node ever tested it, and a successor may not state
more than its nodes attest (D0161's holding).

**RT-M3-01 — code by address** (L4.23). The declared form of a node carries the content
address of any code a parameter names — a predicate; a map **and the schema it declares**;
a monoid or group with its identity and witnesses — so two different codes under one
registered name are two nodes. D0197 closed the predicate half; the map's out-schema is
still resolved from the registry at tick time and appears in no descriptor
(m3-corrections.md §1). L4.23 fails on today's code; Session B lands the remedy. Same name,
different code is only observable across interpreters (within one, re-registration is
refused), so L4.23 compares descriptors printed by fresh interpreters.

**RT-M3-02 — binary nodes through the shipped executor** (L4.24). Every catalogue shape,
driven through `tannen.incremental.advance` by a frozen caller that never declares
`replay=True` on an `anti_join` and chooses integrals or deltas by reading `node.replay`,
reaches the one-shot reference byte for byte. Measured at this freeze: it passes on today's
code, fails on exactly the three `anti_join` shapes when `anti_join` is removed from the
package's replay set, and fails on every `join` shape when `join` forgets its held state.

**RT-M3-03 — operand roles** (L4.25). For every binary operator the package declares, a
step served from a trace recorded under the other operand order equals the same call
against an empty trace store. It is wrong today for `anti_join`, which does not commute,
**and for `join`**, which does, because its state keeps the two inputs by position — so
D0211's "exactly `{anti_join}`" is corrected (D0226). `union` passes. The remedy pinned is
D0211's first: `advance` folds the operand roles into the step's derivation inputs for a
node whose roles are not interchangeable, so the two orders are two derivations because
they are two input values. `derivation_id`'s formula is not widened: owner-signed D0171
ruling (2) stands. The unfrozen pin
`tests/test_incremental.py::test_a_binary_step_id_inherits_derivation_ids_order_insensitivity`
asserts the opposite for `anti_join`; retiring it is a reversed decision and gets its own
record in Session B, as its docstring requires.

## 10. The validation ratchet, applied (D0094; the M2/M3 pattern)

1. **A model beside the laws.** `tests/laws/m4/_boundary_model.py` is a self-contained
   transcription of §2–§7, importing nothing from tannen and using no dataclasses (it is
   loaded by file location under names absent from `sys.modules`). It carries the fakes the
   laws drive instead of the world — `MemoryClient` and `FakeTransport` — and a `Subject`
   interface; `_boundary_subject.py` puts the package behind it and checks `REQUIRED`
   against its own `__dict__`.
2. **The freeze gate.** Every model-checked family passes against the model and fails
   against a stated mutant, at this very commit, with no tannen import
   (`tests/test_law_validation.py`). Eight families, thirteen mutants, each watched dying by
   its family's own assertion: `class-outside-descriptor`, `read-before-capture`,
   `invoke-on-hit`, `key-ignores-descriptor`, `transport-then-refuse`, `zero-means-free`,
   `check-after-call`, `counter-not-fold`, `unreserved-call`, `envelope-drops-usage`,
   `export-accepts-derive`, `overwrite-on-put`, `trust-remote-bytes`.
3. **Generators are shaped, not policed** (D0118): the spend scenarios that matter are
   NAMED and run unconditionally before any draw — zero refuses free, absent class, unit
   mismatch, exact fit, two sessions exhausting one budget, a capture write failing after
   the call, a reservation write failing, a hit being free, a world overrun, the total
   binding across kinds — and every draw reports its shape through `event()`.
4. **Satisfiability, measured.** Because the adapter and the boundary laws cannot run until
   Session B, this freeze ran them against a throwaway prototype of §1 built from the model
   (never committed): every boundary and successor law passed against it, L4.12 across
   fresh interpreters included, and the RT laws failed on today's executor exactly as
   §8 says and passed with the §8 remedies applied.

Every M4 law file declares `VALIDATED_BY` naming its model family, one family per file, or a
`VALIDATION_REASON`: the doorway (a property of an import graph), boundary replay and the
executor laws (machinery — the L1.15/L2.8/L3.15 precedent), and the two differentials, whose
oracle is the model.

## 12. Kill criterion & completion

**Kill criterion.** Any path by which a caller observes an oracle value no capture holds,
a replay reaches a transport, or an admission lets spend exceed a ceiling — a failure of
L4.2, L4.3, L4.4 or L4.5 — is fixed before anything else lands. The response is never to
weaken the rule to what the implementation does, never to narrow the scenarios, and never to
raise a ceiling to make a denial go away. M3's criterion carries on L4.19 unchanged.

M4 is done when:

- `uv run pytest tests/laws/m4` is green with **zero skips**;
- `uv run tannen laws report` shows fresh evidence for L4.1–L4.25;
- `make verify` is green, including `lint-imports` proving the kernel still imports no IO
  and no clock, and L4.9 proving the shell imports them only through the doorway;
- `tests/test_law_validation.py` is green: the model passes every family and every mutant
  dies by the check that names it;
- the RT-M3-01 and RT-M3-03 remedies have landed and the unfrozen swap pin is retired under
  its own record;
- `governance/laws.yaml`'s `pending` list is still empty — or carries an entry with its own
  defect record, per §9;
- every ceiling in `budget.yaml` is still zero unless an owner sitting raised it;
- the M4-close digest is generated.

Session B runs in this worktree, in a fresh session, and never edits a frozen path. If a
frozen law here turns out to be wrong it is not edited: the defect gets a record, the
correction gets a new frozen file, and the old one is marked superseded in the manifest
notes. The record of the mistake is part of the record.
