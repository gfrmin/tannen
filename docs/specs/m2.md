### 0.1 What was missing, stated plainly

M1 shipped `Why`, made `ℤ × Why` the default, and gave every operator a semiring rule
that *is* its provenance rule. It shipped no way to **mint** a ref from data. `Rel(...)`
accepts whatever `Why` a caller hand-writes and the executor's only source is
`Rel.from_value(store.get_value(ref))`, so BRIEF §6's L5 — *delete a source row; every
changed output row must have carried its ref* — was not merely unimplemented at M1, it was
**unstatable**: there were no source rows, and no refs for them. §2 supplies the missing
half and §5 states the law.

## 1. Package layout

New, in the effectful shell — **not** in `tannen.kernel`, so the `kernel-no-io` and
`kernel-no-clock` contracts are untouched:

- `tannen.sources` — `source_row_value`, `source_row_ref`, `ingest`, `lineage`, and
  `Citation`. It reads and writes the store, which is exactly why it is a shell module.

Changed, inside the kernel:

- `tannen.kernel.rel` — the witnessed-row invariant of §3, in `_init`, which is already
  the one place that decides what a retained row may be.
- `tannen.kernel.ops` — `anti_join`'s witness becomes a conjunction (§6, D0132).

The source layer is **not** the capture layer. BRIEF P8's `capture` is oracles only and
arrives at M4; `ingest` is deterministic and reads bytes the store already holds. A
relation it returns enters at `decode` or `derive` like any other.

## 2. Sources (`tannen.sources`)

A **source** is a ref: the identity of bytes hashed outside the system
[cites: pkm-event-identity]. A **source row** is one row decoded out of it. Its ref is the
content address of the value that names both:

```json
{"tannen": "srcrow/1", "source": "sha256:…", "row": {…}}
```

- `source_row_value(source, row)` is that value; `source_row_ref(source, row)` is its
  content address. A `source` outside the pinned grammar is refused by
  `tannen.kernel.refs` — the grammar has one home and this opens no second one
  [cites: provenance-ref-grammar].
- **`ingest(store, source, schema, rows)` writes each `srcrow/1` value into the store
  before it returns the ref** (D0126). Every atom of every `Why` this system mints
  therefore dereferences to a value explaining itself. The alternatives were considered
  and are recorded as rejected: a ref computed but never stored is a citation to a
  document that does not exist, and one ref per *source* rather than per *row* makes L5
  stop discriminating, because deleting any row would then move every output row's
  provenance equally.
- The cost is one store write per distinct row. It is append-only and it is not optimised:
  there is no performance work before M5 (BRIEF §10), and a lineage nobody can follow
  would be the wrong thing made fast.
- The returned `Rel` is over the default `ZxWhy` — deltas *and* support, unasked (§5.5) —
  with each row annotated `(occurrences, Why.of({its own ref}))`.
- **Identical rows in one source are one row.** A source is content-addressed, so two rows
  with the same canonical bytes have the same ref: their counts add and their witness does
  not. Putting an index in the ref would make ingest order-dependent, which is the one
  thing content addressing buys.
- Ingest is idempotent: the store is write-once, so re-ingesting the same source writes
  nothing and returns a `Rel` with the same address (L0.5).
- A row outside the encodable domain is refused by name and **nothing is written for it**
  — the M0 door, unchanged [cites: exactness-and-the-door].

## 3. A retained row is a witnessed row (D0110, owner-authorised)

`Rel` refuses an annotation that claims copies of a row it has no derivation for: nonzero
in the count component, `Why.zero` in the `Why` component, under any semiring carrying a
`Why`. The component is located structurally by `semiring.why_slot` (D0109), so `Z` and
`B` — which make no provenance claim — are untouched.

The check lives in `Rel._init`, beside the existing zero-annotation drop, because that is
already the place that decides what a retained row may be. Being there, it covers the
public constructor, `_from_pairs`, `from_value` and every operator's output at once.
Equivalently: **after zero annotations are dropped, no surviving row has an empty `Why`**
— an annotation that is not the semiring's zero and has an empty `Why` necessarily has a
nonzero count, so the rule needs no second clause.

Three consequences, none of them incidental:

1. `(0, {{r}})` is still retained. It is witnessed and it is not the product zero; it has
   no bag image, which is L1.2 as amended by D0093 and is unchanged here.
2. `to_bag` becomes total over retained rows, and the `anti_join`/π₁ disagreement D0107
   agonised over **dissolves** rather than being decided: the two maps part company only
   on `(n, ∅)`, which is now unconstructible.
3. Two frozen-corpus statements stop being true of reachable values. One is the M1 law
   node D0128 retires (§8); the other is
   `tests/test_provenance_homomorphism.py`, which is unfrozen ordinary coverage and which
   Session B rewrites — its `REACHABLE`/`ANY_ANNOTATION` split collapses to one generator,
   and `test_a_survivors_witness_can_give_an_unwitnessed_row_a_bag_image` is the alarm
   D0110 said should be read the day an ingest path lands. This is that day.

## 4. The deletion homomorphism

For a set `D` of source rows, `R \ D` is the relation ingest would produce from the same
source without them. **Nothing is deleted from the store**: the store is append-only and
write-once (BRIEF §10), and `R \ D` is a new value with a new address. "Deletion" is a
statement about relations, never about bytes at rest.

On annotations, deleting `D` is the valuation sending each atom in `refs(D)` to zero and
every other atom to one. Antichain-normalised `Why` is **PosBool**, so that valuation has
a closed form on support sets, and it is the whole of §5:

> `surviving(w, D) = { S ∈ w : S ∩ refs(D) = ∅ }`, antichain-normalised — and the
> normalisation is free, because a subset of an antichain is an antichain.

## 5. L5 — provenance soundness, at full strength

BRIEF §6 asks for soundness: delete a source row, and every changed output row must have
carried its ref. The true statement is an **iff**, and the iff is what is frozen (D0127):

> **For any graph over the positive fragment and any set `D` of source rows, the witnesses
> of an output row over `R \ D` are exactly `surviving(w, D)` — so the row survives iff
> some support set is disjoint from `refs(D)`.**

Soundness is the corollary in one direction. Stating the weaker form would have been
stating less than is true, and the extra direction is what catches a provenance that
over-cites: a witness that is not really a derivation survives a deletion it should not.

**The positive fragment** is `select`, `project`, `map_rows`, `union`, `join`, `distinct`.
Two operators sit outside it, and each is named rather than approximated:

- **`aggregate`** — the folded value reads the deleted rows' *values*, not merely their
  presence, so deleting a contributor replaces the output row with a *different* row and
  no claim about that row surviving could be true. What holds, exactly, is the theorem on
  the **group key**: project the output onto `by` and §5 applies unchanged. This is the
  same shape as `by` being non-empty (m1 §4.1) — where SQL would invent a NULL, tannen
  states the boundary instead.
- **`anti_join`** — non-monotone, and §6 is its own section.

### 5.1 What is deliberately not claimed

The **ℤ component** is not part of the theorem. It counts derivations, and a semiring that
tracks how many derivations survive a deletion is ℕ[X], which BRIEF §8 puts after M5.
`Why` answers *whether*, not *how many*, and this spec says so rather than letting a law
imply otherwise.

### 5.2 Minimal witnesses (L2.4)

Three claims, and the middle one is the one worth having:

- **antichain** — no support set strictly contains another;
- **sufficiency** — keeping *only* a support set's source rows still yields the row, so it
  is a derivation and not a bystander;
- **minimality** — keeping only a *proper subset* of it does not, so nothing in it is
  surplus.

Minimality is **not** "deleting a proper subset of a witness leaves the row standing": a
join witness `{a, b}` dies when either half goes and is minimal all the same. Getting that
backwards is the first thing a naive reading does, and it is recorded here because the
Session A model was written that way first and the model caught it.

## 6. `anti_join`'s absence witness is a conjunction (D0132)

`anti_join` is outside RA+, so nothing derives what its survivors should cite; the choice
is a **convention**, and this is where the convention is pinned.

A survivor's `Why` gains an atom naming the **right relation's own content address** —
the claim being made is about that relation as a whole at that version, so no row-level
ref can express it. M1 combines that atom with `add`. That reads as **or**, and it leaves
the citation standing as an independent derivation of a row it cannot derive:

```
left  {k:1, x:1}  annotated (1, {{a}})
right {k:2, y:9}  (no matching key)
anti_join(left, right, ("k",))  ==>  (1, {{a}, {addr(right)}})
```

Delete source row `a`: `{addr(right)}` is disjoint from `{a}`, so §5 predicts the row
survives. The left relation is empty, so it does not. **`add` is wrong** and the fix is
`mul`: the claim is *this row's own derivation held **and** the right relation lacked this
key at this version*, so every support set gains the atom.

Three claims are frozen as L2.6:

1. every survivor's **every** support set carries the address (conjunction, not disjunction);
2. an **empty** right operand is cited by nothing — there was nothing to check, so nothing
   to cite, and `anti_join(R, ∅) ≡ R` exactly (L1.8), which a witness added unconditionally
   would break;
3. deleting any row the right operand reads **moves that address**, so no witness of the
   old output survives into the new one: an anti-join's rows are recomputed, never
   inherited. Deletion invalidates the citation rather than appearing in it, which is what
   makes §5 exact for a non-monotone operator.

`src/tannen/kernel/ops.py` is not a frozen path, so this is an ordinary Session B change;
`_model.MUTANTS["antijoin-disjunctive"]` is the M1 behaviour kept as the mutant L2.6 must
kill, so the defect cannot come back quietly.

## 7. Lineage (`tannen.sources.lineage`)

```
Citation(ref, kind, source, row)      kind ∈ {"source-row", "value", "unresolved"}
lineage(store, why) -> tuple[tuple[Citation, ...], ...]
```

Support sets in, resolved citations out, structure preserved exactly. It is a `serve`-layer
read: it changes neither the relation nor the store.

**It is total.** An atom that does not resolve is *classified*, never raised on — and that
is not defensive programming, it is required: §6's absence witness cites a relation's
address, and nothing guarantees that relation was ever stored. A lineage read that can
fail is one nobody puts in a serve path, and an unfollowable citation would make §2's
per-row store write pointless. There is no fourth classification for a malformed atom
because `Why.of` refuses a non-ref by name, so one cannot reach a `Rel`.

## 8. Supersession, mechanised (D0128)

D0106 ruling 2 settled the rule and nothing had yet exercised it: a law found wrong after
its milestone closed is superseded **forward** — a new file under the current milestone's
directory, never an in-place edit, never back-dated into a closed milestone. D0110 is its
first use, and it needs one thing the ruling did not supply: a way for the **old** node to
stop being a false red.

`tests/laws/m1/test_l1_rel.py::test_l1_5_mixing_semirings_is_refused_by_name` constructs
`Rel(("a",), [({"a": 1}, (2, Why.zero))])` as incidental filler — the annotation is not
what the law is about — and §3 makes that value unconstructible. The file is frozen and
sealed, so it cannot be edited, and the claim it makes is not wrong.

- `governance/laws.yaml` names the node, its successor law, the record, and the reason —
  in **two lists**. `superseded` is ACTIVE. `pending` is validated but not active, and
  `scripts/check_laws.py` checks both identically.

  The split is forced, and by the same fact that makes the whole mechanism necessary. At
  the `m2-laws-freeze` commit `Rel` still *accepts* the unwitnessed annotation, so the node
  still **passes** — and a strict xfail on a passing test is an XPASS, which is a red gate.
  A supersession cannot be activated before the change that retires the node has landed.
  The entry is therefore frozen as `pending` data now, its node, successor and record all
  guard-checked at Session A, and **Session B promotes it to `superseded` in the same
  change that lands D0110**. Promotion is a two-line move, and it is the moment the
  retirement becomes true rather than a claim about the future.
- The root `conftest.py` marks each ACTIVE node `xfail(strict=True)`. **Strict xfail, not
  skip and not deselect**, for two reasons. A retired law that stops failing turns the gate
  red, so the supersession is a live assertion about the new behaviour rather than a way of
  looking away (D0092's pass-before/fail-after discipline). And it emits no `SKIP` line, so
  it does not collide with `check_decisions.ALLOWED_SKIP_REASON_PREFIXES` — a custody-set
  allow-list D0124 already flags as too narrow to widen safely.
- `scripts/check_laws.py` fails an entry whose successor law does not exist, whose node is
  absent from the frozen file, which names no record, or which appears in both lists.
- **`tannen.laws.plugin` had to learn about it**, and this is the sharp edge rather than a
  detail. A strict xfail reports as SKIPPED, and the plugin treats any skip in a law as
  "partly run, attests nothing" — so retiring ONE node of L1.5 would silently have stopped
  L1.5, including its three healthy nodes, from ever writing evidence again, and
  `tannen laws report` would have gone red for a law that was fine. The plugin now takes
  the retired nodeids and excludes them from both the run and the expected set. They are
  passed in from `conftest.py` rather than read inside the package: pyyaml is a dev
  dependency, and a governance file is not something the shipped package parses.
- The claim itself is carried forward by L2.2, restated with a witnessed filler. What was
  wrong was the filler, and only the filler.

Checked before freezing: line 244's construction sits **outside** the `pytest.raises`
block, so the node genuinely fails under §3 rather than passing for the wrong reason. A
grep of `tests/laws` confirms it is the only such construction in the frozen corpus.

## 9. The validation ratchet (D0094), and what of it is reachable

D0094 scheduled three parts for M2. Two land here; the third lands in halves, and the
half that does not is queued rather than quietly dropped (D0129, D0131).

1. **A model beside the laws.** `tests/laws/m2/_model.py` is a self-contained
   transcription of §2–§6, frozen inside the seal, importing nothing from tannen — the
   `_fragment.py` precedent (D0089). Every check is written against a `Subject` interface;
   `_subject.py` puts the shipped package behind the same interface. **`TannenSubject`
   deliberately does not subclass the model**: inheriting would let a forgotten method fall
   back to model code and report the model passing while wearing tannen's name, so
   `_model.REQUIRED` is checked against the adapter's own `__dict__` instead.
2. **The freeze gate gains a second assertion.** It is no longer "every law skips" but
   "every model-checked family PASSES against the model and FAILS against a stated mutant".
   Six mutants ship, one per family, paired in `_model.CAUGHT_BY`; a mutant nobody aims a
   check at proves nothing. `MUTANTS["antijoin-disjunctive"]` is tannen's own M1 behaviour.
3. **The gap is countable.** Every frozen law file at or after `governance/laws.yaml`'s
   `declarations_required_from` declares `VALIDATED_BY` or `VALIDATION_REASON` at module
   level, parsed statically by `scripts/check_laws.py` — static like
   `tannen.laws.discovery`, so the check does not depend on the law files being importable
   and a pre-implementation tree reports the whole set rather than nothing. The guard is
   reached from `tests/test_law_validation.py` (the D0070/D0123 pattern: the custodian is
   the floor, and pytest is the distance between weakening a guard and finding out).

   **M0 and M1 are exempt, and counted.** Their law files were frozen and sealed before
   this rule existed, so adding a declaration to one is an edit to a frozen path — the act
   CLAUDE.md forbids — and retrofitting sixteen files by supersession is what D0094 itself
   declined. So the guard prints the exemption as a number instead: today it reads
   *"7 frozen law file(s) declare their validation, 16 exempt"*. **That number is the
   `unvalidated` residue**, and printing it is the cheapest available answer to D0117 —
   the quantity exists, is exact, and is written down somewhere.
   **The `unvalidated` ratchet metric does not land here**: it lives in
   `scripts/gen_projections.py` and `scripts/check_decisions.py`, both custody-set, as do
   the `make verify` and CI lines that would invoke `check_laws.py` directly. Editing any
   of them reddens the gate until a sitting re-signs, so they are queued to the M2 boundary
   (D0131). What is delivered is the measurement and its guard; what waits is the column
   in the digest.

M2's law generators follow D0118's rule: the empty relation is drawn as a **named** case
rather than as a side effect of the size distribution, each shape declares the case it
exists to exercise (a join wants overlapping keys, an anti-join **partial** overlap, a
filter a literal from the column it filters), and every draw reports its shape through
hypothesis `event()`. No thresholds anywhere — D0118 measured why a floor is the wrong
instrument.

### 9.1 The sentinel, and why the freeze is not a check that cannot fail

M1's package is importable already, so a law touching only `tannen.kernel` would **run** at
the freeze commit and fail. `_subject.py` opens with
`pytest.importorskip("tannen.sources")`: while there is no `tannen.sources`, M2 is
unimplemented and every law here is a visible skip.

That is a sentinel, not a fig leaf, and the difference is `tests/test_law_validation.py` —
which imports `_model.py` directly, needs no tannen at all, and runs every check against
the model and the six mutants **at this very commit**. The assertions are exercised before
the freeze and at every commit after it. This is the precise hole D0094 was filed about,
closed for the milestone it was scheduled for.

## 12. Kill criterion & completion

**Kill criterion.** A failure of L2.3 in the **iff** direction is a defect in the `Why`
algebra or in §4's homomorphism, and it is fixed before anything else lands. The response
is never to weaken the law to plain soundness, never to narrow the fragment, and never to
drop a shape from the catalogue: each of those turns a wrong answer into a smaller
question. `_model.py` exists so that the failure has somewhere smaller to be found than a
random pipeline.

M2 is done when:

- `uv run pytest tests/laws/m2` is green with **zero skips**;
- `uv run tannen laws report` shows fresh evidence for L2.1–L2.9;
- `make verify` is green, including `lint-imports` proving the kernel still imports no IO
  and no clock — `tannen.sources` is shell, and a source layer that crept into the kernel
  would be caught there;
- `tests/test_law_validation.py` is green: the model passes and every mutant dies;
- the retired M1 node reports **xfail**, never xpass;
- the M2-close digest is generated.

Session B runs in this worktree, in a fresh session, and never edits a frozen path. If a
frozen law here turns out to be wrong it is not edited: the defect gets a record, the
correction gets a new frozen file, and the old one is marked superseded in the manifest
notes. The record of the mistake is part of the record.
