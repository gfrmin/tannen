## 1. The surface Session B implements

Everything is shell; the kernel contracts are unchanged. The frozen adapter
`tests/laws/m5/_dogfood_subject.py` and every M5 law file are written against exactly these
names; a name not listed is implementation freedom.

**`tannen.cli`** (changed): `tannen run MODULE:CALLABLE --store PATH [--budget PATH |
--budget-override PATH] [--spend]`. `--budget` and `--budget-override` are mutually exclusive
(a usage error, exit 2). The clamp is §6.

**`tannen.dogfood`** (new; library only — it reads no governance file, D0240):

- `select(measurement) -> source id`; `SelectionRefused` (§2).
- `compare(store, corpus, outputs) -> [divergence/1 values]`, `outputs` mapping item id to
  output ref; `IncompleteRun` (§4).
- `run(store, corpus) -> {item id: output ref}`: imports the corpus's `pipeline`
  (`MODULE:CALLABLE`, the operator's code, as `tannen run` names it), opens
  `tannen.oracles.Oracles(store)` — replay-only, the default — and calls
  `CALLABLE(oracles, store, input_ref) -> output ref` once per item, in corpus order.

## 2. The selection rule (`measurement/1`) [owns]

A `measurement/1` record lists candidates, each a Renavon source with `visible_export`, the
`parser_files` counted, `parser_loc` under counter `loc/1` (non-blank physical lines that are
not only a comment, over the named files), and the tannen `operators` its vertical would
require. The schema constrains operator names only in shape; membership is decided against
`tannen.kernel.ops.OPERATORS`, **derived from the package, never listed** (D0171 ruling (3)).
Grade S, frozen with vectors: L5.3.

**The rule** (L5.4), with BRIEF §8's silences pinned:

1. a measurement naming one source twice, or any operator outside the catalogue in ANY
   candidate, is refused whole (`SelectionRefused`);
2. eligible = `visible_export`; none eligible is refused;
3. minimise `(parser_loc × distinct operators, distinct operators, source id as UTF-8 bytes)`.

A tie on the product breaks toward FEWER operators. A further tie is also a tie on LOC, because
the product fixes it, so the source id is the last and total key. At the gate the authorised
measurement, `.dogfood/measurement.json`, must select the vertical the corpus is of, as computed
by the law itself and not only as the implementation reports it.

## 3. The corpus (`corpus/1`) [owns]

"production_output"}]}`. Everything is a name or a content address in the pinned grammar

record. `authorisation` names the decision record that opened door `renavon-first-contact`.
Grade S: L5.5, which also holds the corpus actually present to the schema and to one entry per
item.

**Door 3, in a law** (L5.8). D0019 said the M5 vertical would refuse without the door's
signature. D0240 settles where that refusal may not live: a library enforces the authorisation it
is handed and never reads the constitution. So `tannen.dogfood` does not check it, and L5.8 does.
The named record must be a file under `decisions/`, `tier: C`, `status: accepted`, carrying the

that record is itself queued for the gate sitting (D0257); a different shape there means a
superseding law.

## 4. Byte identity, and replay

"Byte-identical" means bytes. `compare` forgives no trailing newline and no whitespace, and
re-encodes nothing. It returns one `unanalysed` `divergence/1` per item whose tannen output
differs from production's, in corpus order, naming both refs and the first differing byte (the
shorter length when one output is a prefix of the other). It returns none for an identical item,
and it refuses outputs that do not answer exactly the corpus's items (L5.7).

Frozen inputs mean the vertical asks the world nothing: every value it reads is a source or a
capture already in the store. So `run` completes replay-only, and fresh interpreters with
randomised hash seeds answer every item with the same output refs (L5.10; BRIEF §6 L1).

## 5. Divergences, and what "analysed" means (`divergence/1`) [owns]

`{"tannen": "divergence/1", "item", "input", "tannen_output", "production_output", "offset",
"classification", "analysis", "evidence"}`. The classification comes from a closed set:

- `unanalysed`, as the comparator writes it: empty analysis, no evidence;
- `tannen-defect`;
- `production-defect`, which counts as a win and requires at least one evidence ref;
- `input-drift`;
- `specification-gap`.

Every class but `unanalysed` needs a non-empty analysis. Analysis is a separate act from
comparison, and the comparator never classifies. Grade S: L5.6.

**The charter** (L5.9; BRIEF §8), over `.dogfood/corpus.json` and `.dogfood/store/`. Every item
is answered. The LAW reads both outputs' bytes and compares them itself. Every differing item has
an analysed record at `.dogfood/divergences/<item>.json` naming the same refs and offset. No
identical item carries a stale record, and nothing recorded is still `unanalysed`. A corpus
with no items is refused.

## 6. The clamp, and L4.4's third node superseded

Owner ruling D0240 item (2): `tannen run` is clamped to the checked-in `budget.yaml`, with any
other file requiring an explicit `--budget-override`. It is deferred here by D0241, because a
successor law had no legal home inside M4. The rule (L5.1):

- **Without `--spend`**, neither budget flag is consulted, so replay-only refuses a novel
  invocation exactly as L4.4 froze.
- **With `--spend`**:
  - with no flag, or `--budget` naming the checked-in `budget.yaml` at `find_root()`, admission
    is against that file;
  - `--budget` naming any other file is refused as `SpendDenied`, naming `--budget-override`,
    before the transport and with nothing written;
  - `--budget-override PATH` admits against PATH.
- **Admission** is L4.5's: a zero ceiling refuses even a zero-priced call.
- **A capture** made under `--spend` replays without it.

The refusal is `SpendDenied` rather than a new class, so that L4.4's second node keeps reading
`SpendDenied`. Measured against a throwaway prototype of this rule, exactly one frozen node
fails: `tests/laws/m4/test_l4_modes.py::test_l4_4_tannen_run_spend_is_the_one_spelling_that_can_call`.
L4.4's other four nodes pass.

**The supersession, D0128's two lists.** At this freeze the retired node still PASSES (no clamp
yet), and a strict xfail on a passing node is a red gate. So `governance/laws.yaml` carries the
entry under `pending` (node, successor L5.1, record D0258). It was watched: under `superseded`
the node reports failed; under `pending`, passed. **Session B does three things in ONE change:**

1. lands the clamp;
2. promotes the entry to `superseded`;
3. rewrites `tests/test_spend_preconditions.py`'s strict node (D0244 item (3)) from
   `{current-envelope, successor-law, clamp}` to `{current-envelope}`.

The pre-budget lock stays armed on `current-envelope` until D0253's item lands.

## 7. The doorway, derived: L4.9 superseded forward

L4.9 froze BRIEF §5.3's shell half over a hand-written network set and did not scan process
creation at all (RT-M4-02). The custody-set guard `scripts/check_doorway.py` closed both holes
at the M4 sitting (D0248). L5.2 is the frozen judge of the same property. It RESTATES the guard's

the real tree and the residue fixture. The three rules and their doors:

- **network**: outside `tannen.oracles`, `tannen.r2` and `tannen.laws` (the runner), no import
  whose static module-level closure reaches a seed in `{socket, _socket, ssl, _ssl}`;
- **process**: outside `tannen.oracles` and `tannen.r2`, no module the `shell-no-subprocess`
  contract forbids, and no `os` process primitive;
- **clock**: outside `tannen.oracles` and `tannen.laws`, no module the `kernel-no-clock`
  contract forbids.

It has positive controls on the derivation. The residue fixture must fail exactly its six
payloads (D0246 A4). D0248 item (5)'s limits are carried in the law's docstring as limits. L4.9
is retained, unedited, and still runs: it is weaker, not false, so no node is retired (D0225's
pattern).

## 8. Liveness: one corpus, one gate, two sessions

A milestone is live from its first evidence record, and in a live milestone every law without a
fresh record is stale (D0227). Renavon's frozen inputs and outputs can never enter this public
repository, so CI can never run the charter. By owner ruling of 2026-09-15 (D0259), **every M5
law file skips unless BOTH hold**:

- an authorised corpus is present at `.dogfood/corpus.json`;
- `tannen.dogfood` imports.

The second condition closes the window in which the self-contained laws would attest while the
vertical's laws skipped. The window was watched: with the corpus present and no `tannen.dogfood`,
all ten files skip.

`.dogfood/` is gitignored and holds `corpus.json`, `measurement.json`, `store/` and
`divergences/`. **M5 stays pending in CI for good, and M5's close is attested on the owner's
machine.**

## 12. Kill criterion & completion

**Kill criterion.** Two failures are fixed before anything else lands:

- a failure of L5.9, meaning an item that differs from production with no analysis;
- a failure of L5.8, meaning a corpus read without the owner's door signature.

The response is never to normalise the comparison, never to drop an item from the corpus, never
to classify a divergence to make it go away, and never to widen the authorisation.

M5 is done when all of the following hold:

- on the owner's machine, with the authorised corpus present, `uv run pytest tests/laws/m5` is
  green with **zero skips**, and `uv run tannen laws report` shows fresh evidence for
  L5.1–L5.10;
- every divergence is analysed, and each `production-defect` is reported to its owner by the
  owner's hand. Bytes leaving the boundary are door 2, never this repository's act;
- `make verify` is green in CI, where M5 reads pending;
- `governance/laws.yaml` carries the §6 entry under `superseded`, and `tests/test_spend_preconditions.py`
  reads `{current-envelope}` unless D0253's item has since landed;
- every ceiling in `budget.yaml` is still zero unless a pre-budget sitting raised it;
- the M5-close digest is generated, and the owner countersigns `m5-close` (BRIEF §8: "author
  countersign only at M0 (opening) and M5 (close)").

Session B runs in the m5 worktree, in a fresh session, and never edits a frozen path.
