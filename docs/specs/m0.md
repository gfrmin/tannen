## 2. Canonical encoding (`tannen.kernel.encoding`)

Follows the production `canonical_json` precedent (renavon-monorepo
`shared/src/shared/ingest/descriptor.py::canonical_json` at the pinned commit
`ab68dd9c`: `sort_keys` + separators `(",", ":")` + `ensure_ascii=False`, hashed as
UTF-8), extended per BRIEF §4 with NFC, exact integers, tagged decimals, and float
rejection [cites: exactness-and-the-door]. Pins (decision D0031):

- **Value domain**: `None`, `bool`, `int` (unbounded), `str`, `decimal.Decimal`,
  `list` of values, `dict` with `str` keys. Anything else — **bare `float` above
  all**, plus `bytes`, tuples, sets, custom objects — raises
  `CanonicalEncodingError`. (`bool` is checked before `int`.)
- **NFC**: every `str` (values and keys) is NFC-normalised before encoding. Two
  distinct keys that NFC-normalise to the same string raise
  `CanonicalEncodingError` (a silent merge would forge identity).
- **Key order**: object keys sorted by Unicode code point of the NFC-normalised key
  (equivalently: byte-wise over their UTF-8).
- **Integers**: exact decimal literals, no exponent, no leading zeros; `-0 → 0`.
- **Decimals**: encoded as the tagged object `{"$decimal":"<s>"}` where `<s>` is the
  exponent-free minimal form of the *normalised* value (`1.50 → "1.5"`,
  `1E+2 → "100"`, `-0 → "0"`). `NaN`/`Infinity` decimals raise. Numeric equality ⇒
  identical encoding.
- **Reserved key**: a map containing the key `"$decimal"` raises
  `CanonicalEncodingError` — the tag namespace is refused by name, never silently
  escaped (the door discipline). Future tags extend the reserved set only with a
  descriptor bump.
- **`null`**: the encoding of `None`, understood as the image of `Option.none`
  (P7). SQL-NULL semantics never enter; there is no NULL in the data model.
- **Strings**: JSON escaping exactly as the precedent emits it (`ensure_ascii=False`;
  mandatory escapes `\" \\ \b \f \n \r \t`, other control characters as `\u00XX`).
- **Floats and the door**: no float is encodable in M0 at all. `Lossy(f, grid)` —
  the explicit, priced door of BRIEF §5.8 — arrives with the Rel layer at M1 and
  lowers a float to a tagged decimal via a declared grid; M0 ships only the refusal.
- **Decoding**: `decode_canonical(bytes)` inverts the encoding: strict JSON parse
  where any float literal (a number with `.`, `e`, or `E`) raises, `{"$decimal":s}`
  lifts to `Decimal(s)`, everything else maps back directly. Round-trip is law L0.4.

API: `encode_canonical(value) -> bytes`, `decode_canonical(data: bytes) -> value`,
`content_address(value) -> str` (the ref `sha256:<64 lowercase hex>` of the canonical
bytes — the pinned grammar [cites: provenance-ref-grammar]), and
`CanonicalEncodingError`.

## 3. Store (`tannen.store`)

Content-addressed, write-once, append-only, local filesystem (BRIEF §4); the cache
is a view over what happened, and recording makes no truth claims
[cites: pkm-event-identity]. One address space: an address is the ref of the stored
bytes; a *value* is stored as its canonical encoding, a *source* as its raw bytes
(source identity = `sha256` of bytes computable outside the system, pkm §1).

API and semantics:

- `Store(root: path)` — creates/opens a store rooted at a directory.
- `put_bytes(data) -> ref`; `put_value(value) -> ref` ≡ `put_bytes(encode_canonical(value))`.
  Idempotent: re-putting existing content is a no-op returning the same ref (L0.5).
- `get_bytes(ref) -> bytes`; `get_value(ref) -> value`. The store verifies on read:
  bytes that no longer hash to `ref` raise `IntegrityError` (L0.5).
- `has(ref) -> bool`.
- **No delete, no overwrite** — the API simply has no such operations, and distinct
  content can never collide onto one address by construction.
- `gc() -> str` **prints and returns a refusal** and changes nothing (L0.6); the
  refusal names the Tier-C rule (`store-mutation` is guard-enforced; the rule change
  is the owner's).

On-disk layout is implementation freedom within these laws, with one requirement:
bytes at rest are exactly the bytes put (no wrapping, so `sha256sum` on the file
reproduces the address — debuggable from first principles).

## 4. Descriptors (`tannen.kernel.descriptor`)

Descriptor identity per BRIEF §4, aligned with the pkm event tuple ("what would make
this a different event belongs in the hash") [cites: pkm-event-identity]
[cites: pkm-determinism]:

- `descriptor_id(kind, name, code_hash, params_hash) -> ref`: the content address of
  the canonical encoding of `{"kind":…,"name":…,"code_hash":…,"params_hash":…}` —
  all four are strings; the two hashes are themselves refs in the pinned grammar.
- `derive_label(module_path, name, seq) -> str`: the human label is a *pure
  function* — `"<module_path>/<name>@<seq>"` — so there is no "forgot to bump"
  state (§5.2); the registering decorator (M1) supplies the inputs, and `seq` is
  the count of distinct prior descriptors for `(module_path, name)`.
- Reproducibility classes (`bit` / `in-distribution` / `non-reproducible`) are pkm's
  declared-per-producer property; they enter descriptors with oracles at M4 and are
  out of M0 scope [cites: pkm-determinism].

## 6. Evidence records (Grade-S, owned; ships with these laws — BRIEF P6, §7)

Every law run emits a content-addressed evidence record validating against
`governance/schemas/evidence-record.schema.json` (frozen; vectors under
`tests/laws/evidence-vectors/`). The record's id is the content address of its
canonical encoding. This is the future belief-update stream for the Governor seam;
M0 ships schema + vectors + emission, nothing smarter.
