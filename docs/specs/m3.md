## 2. Delta-capable semirings

### 2.1 `negate`, and who has it

`diff` needs subtraction, and subtraction is declared, never assumed. A semiring is
**delta-capable** when every component of its (possibly product) structure is one of:

- a **group component** — it declares `negate`, and `add(a, negate(a)) == zero` is
  checked at the same place the other axioms are (law L3.1). `Z.negate(n) = -n`.
- a **`Why` component** — `negate(w) = w`, a fixed point. `Why` is a join-semilattice
  under `add` (idempotent, no inverse), and pretending otherwise is exactly the mistake
  §6 exists to handle honestly: counts move by the group; witnesses never move
  backwards, they are *filtered* (§3.3, §6).

`B` declares no `negate` and is **refused by name** by every delta operation: a set
semiring has no retractions, and inventing symmetric difference for it would be the
silent coercion the door forbids [cites: exactness-and-the-door]. `Z`, `ZxWhy`, and any
product of group and `Why` components are delta-capable. `is_delta_semiring` is the
structural test, beside `is_bag_semiring`, and every delta operation additionally
requires bag structure — the normalisation in §3.3 is stated in terms of the bag image.

**No M1 refusal lifts.** `Z.multiplicity` and `Z.collapse` still raise on a negative:
a delta has no bag image, and M1's answer — refusing is honest, guessing is not — is
still the right one. What M3 adds is the place where negatives are *lawful* (§3.4), not
a meaning for the question they made unanswerable. Frozen L1.2 stays true by design.

### 2.2 `why_slots` — the RT-M2-04 closure

M2 §3 claims the witnessed-row invariant holds "under any semiring carrying a `Why`".
The shipped locator (`why_slot`) checks self/left/right in fixed order and returns **at
most one** location, so `product(Why, Why)`, `product(ZxWhy, B)`, `product(Z, ZxWhy)`
and `product(ZxWhy, ZxWhy)` all carry a `Why` the door never looks at — the frozen
claim was stronger than the shipped check (RT-M2-01's sibling finding; D0142 routed the
fix here). `why_slots(S)` returns **every** `Why` location by recursive descent over the
product structure; the witnessed-row check refuses a surviving row if **any** located
`Why` is empty; `why_slot` remains as the single-slot accessor, defined over
`why_slots`. No frozen law node constructed a multi-`Why` semiring (checked before this
freeze: the frozen corpus builds only `product(Z, Why)` and `product(Z, Z)`), so no
node retires — the frozen *prose* was falsified, and that defect carries a decision
record (D0161), not a supersession entry.

`anti_join` under a multi-`Why` semiring is **refused by name**: its absence witness
(M2 §6) conjoins one address into "the" `Why`, and a semiring with two `Why` slots gives
that convention two inequivalent readings. Refusal is the honest door until a law, not
an accident of slot order, decides [cites: exactness-and-the-door]. L3.13 freezes both
behaviours.

### 2.3 The encode gate — the RT-M2-07 closure

`Why.of` refuses a non-ref atom by name, and M2 §7 leans on that refusal for
`lineage`'s totality ("a malformed atom … cannot reach a `Rel`"). But `_Why.encode`
re-checked nothing, so a `Why` built by operator arithmetic on a hand-crafted element —
or by any future code path that skips `of` — could put a non-grammar atom into a
canonical form and therefore into the store. The gate: `encode` verifies every atom
against the pinned grammar and raises by name [cites: provenance-ref-grammar]. The red
team measured the gate against the full frozen suite before proposing it (665 nodes
green), so this closure costs nothing that was ever legitimate. L3.14 freezes it:
**no spelling puts a non-grammar atom into a `Rel`, a `to_value`, or a content
address**.

## 3. The delta calculus

### 3.1 A delta is a `Rel`

**A delta is a `Rel` over the same semiring as the relation it changes.** There is no
`Delta` type. `Rel` already constructs negative ℤ counts (nothing in it inspects sign);
the `rel/1` canonical form already encodes them; and the witnessed-row invariant already
does the right thing unprompted — `(-1, {{r}})` is accepted and `(-1, ∅)` is refused,
so **a retraction owes provenance exactly as an arrival does** (§3.2, D0110's rule
working one milestone past its author's intent). A wrapper type would double every
bilinear rule's signature, fork the store format, and contradict P4's one-type
principle; DBSP itself draws no such distinction — a delta is an element of the same
group. (D0156.)

The **empty delta** is `Rel(schema, [])`. A source delta is what `ingest_delta`
returns: arrivals annotated `(+occurrences, Why.of({own ref}))`, retractions
`(-occurrences, Why.of({own ref}))` — the ref of the very row being retracted, minted
and written to the store exactly as `ingest` writes it, so a retraction's witness
dereferences to the row it removes [cites: pkm-event-identity]. Retracting a row whose
canonical bytes were never ingested is not detectable at `ingest_delta` (it is
deterministic and store-write-only) and is caught at `apply`, where it is an
over-retraction (§3.3).

### 3.2 `diff`

`diff(new, old)` — both over the same delta-capable bag semiring and schema — is the
delta that moves `old` to `new`, per canonical row:

- group components: `add(a_new, negate(a_old))`, the group difference;
- `Why` components: **`new`'s where the row occurs in `new`; `old`'s where it does
  not** — so a pure retraction is witnessed by what it retracts, and every other row
  speaks with the new relation's voice;
- a row whose annotation is identical in both is omitted;
- a row present in both whose group components agree but whose `Why` moved is emitted
  with group-zero components and the new `Why` — the "annotation moved" delta, which is
  how a replacement operator's re-cited address propagates (§4, §6).

`diff(R, R)` is the empty delta, and `diff` never consults the bag image, so it is
total over cone and non-cone operands alike — deltas can be diffed.

### 3.3 `apply`, and its normalisation order

`apply(base, delta, dead)` — `base` cone-valued, `dead` a set of refs (§6's ledger) —
is pointwise addition followed by three normalisation steps **in this order** (D0157):

1. **the cone check** — any row whose group component leaves the non-negative cone is
   an **over-retraction, refused by name**, with a message naming the row and the
   shortfall. This is where m1 §4.4's promised loud break lands: at the operation whose
   arguments made the question askable, not at a distant `to_bag`.
2. **the group-zero drop** — any row whose applied annotation is zero in **every group
   component** is dropped, `(0, {{r}})` included. `(1, {{r}}) + (-1, {{r}})` cancels
   *out of the relation*: the reference (one-shot ingest of the net rows) has no such
   row, and byte identity (§5) is the law. The criterion is the group components, not
   the bag image, deliberately: a positive count whose `Why` is empty must fall through
   to step 3's alarm, never be dropped as bag-empty. Construction is untouched — a
   caller-built `(0, {{r}})` is still retained (frozen L1.4, D0093); `apply` is a new
   operation choosing what to *emit*, which no frozen node constrains.
3. **the valuation** — every surviving row's every `Why` is filtered by
   `surviving(w, dead)` (M2 §4, verbatim, now code). A row whose count survives but
   whose every witness dies is then refused by the witnessed-row invariant —
   unreachable when the calculus is right, and the calculus's own alarm when it is not.

The valuation pass runs over the **entire result**, not only delta-touched rows:
uniform, deterministic, and unoptimised on purpose (BRIEF §10). `apply(R, ∅, dead)`
is `R` byte-identically for any `R` the calculus produced under `dead` — normalisation
is idempotent — which is BRIEF L2 at the calculus level; L3.2 freezes it, and the
executor-level form (an empty tick moves nothing, trace hits included) is L3.15's.

### 3.4 Where negatives are lawful — the D0109 answer

> **A raw delta never takes operand position at `distinct`, `aggregate`, `anti_join`,
> or `to_bag`. Negative counts are lawful in delta position only — the arguments of
> `negate`, `diff`, `apply`, and the linear and bilinear rules — and the integrated
> operators consume integrals, which the executor keeps inside the cone at every
> prefix of every stream (L3.4).**

D0109 asked what `anti_join` should answer when a delta reaches it, and recorded that
the M1 raise "is not an answer". The answer is that the question marks an executor bug,
and the raise is the guard that catches it: the delta rule for a non-monotone operator
is **replacement over integrals** (§4), retractions are applied to the right integral
*before* absence is judged, and absence is judged against the resulting cone-valued
relation — the only relation about which "this key is not there" is a proposition
rather than a guess. The cone raises at `multiplicity`/`collapse`/`anti_join` therefore
do not expire; they are **re-commissioned** as the tripwire proving the executor kept
its promise, and D0114's demand — an answer, not a re-reading — is discharged by the
mutant that feeds the delta in anyway and must die (`antijoin-eats-delta`, §9). L3.7
freezes both halves: the replacement forms agree with the reference, and the raises
still raise. (D0158.)

## 4. Per-operator delta rules (derived, never hand-written — P5)

| Operator | Delta rule | Derivation |
|---|---|---|
| `select`, `project`, `map_rows`, `union` | **the operator itself**: Δout = op(Δin) | linear — DBSP's rule for linear operators; the M1 semiring rules are sign-blind (they use `add`/`mul` only, never the bag image), so the shipped operators already compute their own delta form |
| `join` | Δout = `join(ΔA, B_old) ⊎ join(A_new, ΔB)` | bilinear — the **two-term form is pinned** (D0159): on group components it equals `A_new⋈B_new − A_old⋈B_old` outright, and its equivalence to the three-term expansion `ΔA⋈B_old ⊎ A_old⋈ΔB ⊎ ΔA⋈ΔB` is a law clause (L3.6). Pinned because the both-old-sides spelling `ΔA⋈B_old ⊎ A_old⋈ΔB` is the classic off-by-one — it drops the same-tick co-arrival term, and it is kept as a mutant (§9) |
| `distinct`, `aggregate` over a `Monoid` | **replacement at the node**: recompute op over the new input integral, which *is* the new output integral; Δout = `diff(out_new, out_old)` for the parent | DBSP's `op^Δ = D ∘ op ∘ I` for the non-linear operators, taken literally and unoptimised (BRIEF §10). Neither operator ever **extends** a support set, so the nodes above them stay safely delta-maintained |
| `anti_join` | **replacement, contagious upward**: the node *and every node above it* replays over its children's integrals each tick; Δout = `diff` throughout, for the record | the conjunction is the one operation that extends an existing support set, and its ∅→non-empty transition mints a witness that **strictly contains** the witness minted while the right operand was empty (frozen L2.6 clause 2: an empty right is cited by nothing). The dominated stale set carries no dead atom to filter on, so antichain normalisation silently keeps the stale claim under apply-maintenance — a semilattice cannot subtract. **The model found this during pre-freeze validation** (an `interleave` stream over `join-then-anti`), the unsound variant is kept as the mutant `antijoin-delta-maintained`, and replaying is the honest rule, priced by BRIEF §10. Replacement is also what M2 §6 clause 3 already promised: "an anti-join's rows are recomputed, never inherited" |
| `aggregate` over an `AbelianGroup` | **subtractive**: each touched group's folded value is maintained by folding arriving contributions and `inverse`-folding retracted ones; Δout retracts the old output row and asserts the new one | this is where BRIEF P5's "abelian group for subtractability" engages — the first consumer of `tannen.kernel.algebra.AbelianGroup`, whose declared `inverse` becomes load-bearing and whose declared laws L3.8 property-tests directly (BRIEF L3's "declared-monoid laws tested directly"). The subtractive and replacement forms must agree byte-identically, and that agreement is the law (D0160) |

The rules live in `tannen.kernel.delta` as pure functions taking every relation they
read — deltas, old and new integrals — as arguments. Nothing in the kernel holds
state; the executor (§7) is where state lives, because state is a stored value.

## 5. The equality notion: byte identity, earned

L2 (idempotency), L3 (convergence) and L4 (incremental ≡ reference) are all stated as
**content-address equality** — `≡` is the same relation L1 gave replay, and the same
one the golden corpus pins [cites: pkm-determinism]. Not equality of bag images, not
equality of the ℤ component: the frozen suite already knows those quotients as *weaker*
statements (L2.5 states inertness through the bag image precisely because the whole
value carries more).

For pure arrivals byte identity is free, and saying why says what the mechanism is: a
`srcrow/1` ref depends on `(source, row)` only — never on batch, order, or count — so
any partition of a source's rows unions identical refs idempotently while the counts
add commutatively. For retractions the obstruction is real: `Why` is PosBool, has no
subtraction, and pointwise addition leaves the *cumulative* run's witnesses where the
reference has the *net* run's. The obstruction is exactly M2's deletion theorem read
through time: the cumulative `Why` relates to the net `Why` by the valuation at the
refs the stream killed, so `surviving(w, dead)` — applied by `apply`, with `dead`
supplied by the ledger (§6) — recovers the reference **exactly on the positive
fragment**, and L3.11 freezes that as the residue theorem: frozen L2.3 applied to the
atoms time deleted. `anti_join` sits outside it for the reason §4 states, and its
byte identity is earned by replay instead. Rejected, and recorded as rejected (D0157):
equality up to bag image (states less than is true and silently abandons BRIEF §5.5's
promise that the default pipeline's provenance survives a delta); one-sided witness
containment (needs the same residue machinery to state that the valuation needs to
run, and buys a weaker law with it).

### 5.1 What is deliberately not claimed

Byte identity is claimed for the executor's integrals against the reference over net
sources — not for intermediate deltas, which are evaluation artifacts (a different
partition produces different deltas on the way to the same integrals), and not for the
trace store's contents (different streams are different derivations, correctly — see
§7). And `Why` under retraction is exact only *because* the valuation runs, and
through `anti_join` only *because* the contagion rule replays: a group-valued
provenance (ℤ[X]-shaped) would subtract witnesses natively and need neither. That is
the post-M5 ℕ[X] seam, named here so both boundaries are stated rather than met — §4's
∅→non-empty transition is what that seam's absence costs, measured.

## 6. The ledger

The valuation needs to know what died. The **ledger** is a content-addressed value,
threaded by the caller through every step [cites: pkm-event-identity]:

```json
{"tannen": "ledger/1", "dead": ["sha256:…", …]}
```

the list sorted, deduplicated, and refs in the pinned grammar
[cites: provenance-ref-grammar].

**`dead`** — srcrow refs whose net count in their source is now zero. Maintained at
source advances only: an arrival removes its ref **before** the source's `apply`
(resurrection — the ref is the same because the bytes are, and applying first would let
the valuation kill the very witness the arrival carries; the model's
`retract-rearrive` stream found the wrong order during pre-freeze validation); a
retraction that empties a row's count adds its ref after.

That is the ledger's whole content. An earlier draft carried a second list — `retired`
`anti_join` citation addresses — and the model refuted the mechanism it served
(apply-maintenance through `anti_join`, §4): under the contagion rule a superseded
address never reaches an integral in the first place, because everything that could
cite it replays. The ledger is data on the run, not a mutable global: each `advance`
takes a ledger ref and returns one (§7), so the kernel stays pure and the executor's
state is inspectable like any other value. (D0163.)

## 7. The incremental executor (`tannen.incremental`)

**Per-node, caller-composed — no graph object.** M1's executor is deliberately
caller-side (`Node`, one derivation at a time), and nothing in BRIEF §8's "delta
executor" mandates a circuit runtime; L4's "random composite graphs" live where M2
already put composite plans — the frozen model's tuple-tree plan catalogue (§9). A
graph representation would be API surface with no law of its own; it can arrive at M4+
with a law if demand appears.

- **`DeltaNode`** — a *declared* operator application: operator name plus its
  parameters (`on`, `columns`, the monoid, …), as data. Incrementality is derived from
  declared structure (P5), and a registered transform's body is opaque — so the
  incremental executor runs declared nodes, and arbitrary transforms remain the
  reference executor's domain. A `DeltaNode`'s descriptor is the content address of its
  declared form (`deltaop/1`: operator name, canonical params), so two spellings of the
  same node are the same descriptor [cites: pkm-event-identity].
- **State** is a content-addressed `incstate/1` value holding the node's integral refs
  (input integrals where the rule needs them, the output integral always). "The
  executor's state" is therefore a value in the store like any other — nothing hidden,
  nothing mutable.
- **`advance(store, traces, node, state_ref, delta_refs, ledger_ref)`** returns the new
  state ref, the emitted output delta's ref, and the (possibly extended) ledger ref. A
  source advance consumes an `ingest_delta` result instead of upstream deltas and is
  what maintains `dead`. A **tick** is the caller advancing sources first, then derived
  nodes in its own topological order, threading the ledger through; the deltas it
  passes between nodes are the ones `advance` returned. **A node is delta-maintained
  iff no `anti_join` lies at or below it** (§4's contagion rule): at and above an
  `anti_join` the caller passes child *integral* refs and `advance` replays, still
  emitting Δout as the `diff`. Everything `advance` computes goes through the calculus
  of §3–§4; every integral it stores is cone-valued, valuation-filtered, and witnessed
  (L3.4).
- **Every step is its own derivation**: the existing `derivation_id` over the step's
  descriptor and its *content-addressed inputs* — `(state_ref, ledger_ref, sorted
  delta refs)`. One derivation, one output, holds because a step is a pure function of
  those inputs; `TraceStore`, `AlwaysRebuild` and `VerifyingTrace` are reused **as
  is**. Replaying a stream hits traces; a reordered stream is a different sequence of
  derivations — correctly, they are different events [cites: pkm-event-identity] — and
  L3.9/L3.12 assert the *final integrals* converge byte-identically all the same.
- A step whose operator quarantines writes no trace and leaves state unmoved (P3,
  matching the reference executor's rule). Quarantine rows are reports about a tick,
  never state.

## 9. The validation ratchet, applied (D0094; the M2 §9 pattern, unchanged)

1. **A model beside the laws.** `tests/laws/m3/_model.py` is a self-contained
   transcription of §2–§7, frozen inside the seal, importing nothing from tannen (the
   `_fragment.py`/`_model.py` precedent, D0089): the calculus, the derived rules, the
   ledger, a step interpreter over tuple-tree plans (the M2 catalogue grain, plus
   delta-motivated shapes), the perturbation streams, and the one-shot reference.
   Every check is written against a `Subject` interface; `_subject.py` puts the shipped
   package behind the same interface, opens with
   `pytest.importorskip("tannen.incremental")` — the module M3 introduces, so while it
   does not exist every law here is a visible skip — and deliberately does not subclass
   the model's `Subject`: `_model.REQUIRED` is checked against the adapter's own
   `__dict__` (M2 §9's reason, unchanged).
2. **The freeze gate**: every model-checked family PASSES against the model and FAILS
   against a stated mutant, at this very commit, with no tannen import
   (`tests/test_law_validation.py`, which needs only `_model.py`). Nine mutants ship,
   paired in `_model.CAUGHT_BY`; two are tannen's own tempting wrong behaviours kept as
   mutants — `apply-keeps-zero-rows` (the "consistency with L1.4" mistake) and
   `antijoin-eats-delta` (the D0109/D0114 mutant); `why-slot-first-match` is the
   shipped M2 locator itself, the `antijoin-disjunctive` precedent exactly; and
   `antijoin-delta-maintained` is **this spec's own first draft**, refuted by the model
   during pre-freeze validation (§4) and kept runnable — the record of the mistake is
   part of the record.
3. **Generators are shaped, not policed** (D0118, D0130): every perturbation stream is
   a named case declaring what it exercises, reported through hypothesis `event()`, no
   thresholds. The streams: `one-shot` (the degenerate single batch, drawn by name),
   `empty-batch` (L2's case), `partition-k` (random partition, permuted batch order),
   `interleave` (batches alternating across sources), `arrive-retract` (full
   retraction), `partial-retract` (retract fewer occurrences than arrived),
   `retract-rearrive` (the ledger's resurrection case), `retract-to-empty` (a source
   netting to nothing), `same-tick-co-arrival` (both join operands move in one tick —
   aimed at the dropped ΔA⋈ΔB term), and `right-moves` (an anti_join's non-empty right
   operand changing while a left row survives throughout — the superseded-address case,
   drawn on purpose after 25 accidental draws never produced it, which is D0118's rule
   paying for itself a second time). Streams live in `_model.py` beside the shapes: one
   more frozen helper file would be one more bare-import oracle surface for no
   separation the M2 precedent needed.

Every M3 law file declares `VALIDATED_BY` naming its model family — one family per
file — except `test_l3_executor.py` (machinery exercised through the real store and
traces — the L2.8 precedent) and `test_l3_differential.py` (its oracle IS the model,
so naming a family would be circular — the L2.9 precedent), which declare a
`VALIDATION_REASON`. `tannen.laws.plugin` derives
its oracle-shadow set from `tests/laws/m*/_*.py` off the filesystem (D0142), so M3's
model is covered by that guard from the moment it is frozen, with no enumeration to
extend.

### 9.1 The supersession audit, and its null result

M3 changes kernel semantics that frozen suites exercise, so every plausibly-falsified
frozen node was audited before this freeze (D0164): L1.9's cone node quantifies over
non-negative inputs its generators actually draw — no operator's behaviour on those
inputs changes; L1.2's negative refusals are deliberately kept (§2.1); the product
nodes construct no multi-`Why` semiring (§2.2); L2.2–L2.6 are stated over one-shot
ingest and are what the incremental path must *agree with*, not what it replaces —
L2.6 clause 3 in particular is the promise §4's replacement rule keeps.
**`governance/laws.yaml`'s `pending` list is empty at this freeze**, and if Session B
discovers the audit wrong, the mechanism is D0128's: record, supersede forward, never

## 11. Kill criterion & completion

**Kill criterion.** A failure of L3.12 — the executor's integrals diverging from the
reference — is a defect in the calculus (§3), the ledger (§6), or the residue theorem's
premises, and it is fixed before anything else lands. The response is never to weaken
`≡` to a quotient, never to shrink the catalogue, and never to drop a stream shape:
each of those turns a wrong answer into a smaller question. `_model.py` exists so the
failure has somewhere smaller to be found than a random pipeline, and L3.11 exists so
the `Why` half of a divergence is separable from the count half.

M3 is done when:

- `uv run pytest tests/laws/m3` is green with **zero skips**;
- `uv run tannen laws report` shows fresh evidence for L3.1–L3.16;
- `make verify` is green, including `lint-imports` proving the kernel still imports no
  IO and no clock — `tannen.kernel.delta` is pure, `tannen.incremental` is shell, and a
  ledger that crept into the kernel would be caught there;
- `tests/test_law_validation.py` is green: the model passes every family and every
  mutant dies by the check that names it;
- the M1 node D0128 retired still reports **xfail**, never xpass, and
  `governance/laws.yaml`'s `pending` list is still empty — or carries an entry with its
  own defect record, per §9.1;
- the M3-close digest is generated.

Session B runs in this worktree, in a fresh session, and never edits a frozen path. If
a frozen law here turns out to be wrong it is not edited: the defect gets a record, the
correction gets a new frozen file, and the old one is marked superseded in the manifest
notes. The record of the mistake is part of the record.
