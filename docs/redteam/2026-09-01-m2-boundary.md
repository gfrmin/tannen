## RT-M2-01 — The differential oracle can be replaced by name, making BRIEF §6's kill-criterion law vacuous while 113 tests pass. **Critical.**

**This is RT-M1-01 again, at triple the surface.** M1 found that a frozen oracle module imported
by bare name can be shadowed through `sys.modules`. The closure was a collection-time check in
`src/tannen/laws/plugin.py` — but it watches **one hardcoded module name**:

```python
_ORACLE_MODULE_NAME = "_fragment"                                   # plugin.py:50
_ORACLE_REL_PATH    = Path("tests") / "laws" / "m1" / "_fragment.py"  # plugin.py:51
```

M2 then introduced **two more** bare-imported oracle modules, neither covered, across seven
frozen law files:

```
test_l2_antijoin.py:20      import _model as M
test_l2_antijoin.py:21      from _subject import TANNEN
test_l2_differential.py:15  import _model as M
test_l2_inertness.py:17     import _model as M
test_l2_lineage.py:15       from _subject import Rel, Why, sources
test_l2_provenance.py:19    import _model as M
test_l2_sources.py:15       import _model as M
test_l2_executor.py:15      from _subject import ops, sources
```

**`tests/` is not sealed.** `governance/tier-c.yaml:77-80` seals `tests/laws`, `tests/poison`
and `governance/schemas` — so a new `tests/_model.py` and a new `tests/conftest.py` need no
manifest row and break no seal.

**Reproduction** (sandbox copy of the worktree; the real tree was never touched). A decoy
`tests/_model.py` re-exporting the frozen module, and a `tests/conftest.py` that claims the name
before `tests/laws/m2/` is collected:

```
[PROBE] sys.modules['_model'].__file__ = …/sb-f2/tests/_model.py
[PROBE] marker = tests/_model.py DECOY, not the frozen tests/laws/m2/_model.py
34 passed in 27.68s
```

The decoy is what answers to the name **during the run**, and the plugin's abort never fires.

**The payload.** L2.9's entire body is one call into the model — `test_l2_differential.py:38`,
`M.check_differential(TANNEN, shape, tables)`. So the decoy needs one stub:

```python
def check_differential(subject, shape, tables):
    return None
```

```
[PROBE] marker = HOSTILE decoy: check_differential neutered
34 passed in 25.46s

$ pytest tests/laws/m2 -q
113 passed in 82.89s
```

**L2.9 — BRIEF §6's differential kill criterion, the law whose whole purpose is to catch a
wrong answer — is now vacuous, and the entire M2 law suite is green.** And the guard that
exists for exactly this attack says nothing.

**The manifest stays green too**, because neither decoy is under a seal:

```
$ python -I -P scripts/check_manifest.py     # with both decoys present
check_manifest: OK — frozen paths intact; seals unbroken; custody set current; …
```

**Severity: critical.** M1 rated the `_fragment` version critical for reaching the kill criterion
"without touching a single frozen or manifested byte". This is the same reach, with three module
names instead of one, and it lands on the law that BRIEF §6 nominates as the thing that must
never silently pass. Every M2 law that consults the model — not just L2.9 — is affected: a decoy
controls the standard tannen is compared against.

**Why the M1 closure did not cover it.** The M1 fix was written as a *specific* defence
("defence in depth, not the naming hazard itself" — D0104's own words), pinning one module name
and one path. RT-M1-01's report said plainly that the actual fix is a package-qualified import
in the frozen file, needing the owner's key, and queued it. That queued item was never done, and
M2 then widened the hazard it was queued for. **This is the cost of the partial closure coming
due**, not a new class of defect.

**Proposed closure.**

1. **Generalise the guard now** (`src/tannen/laws/plugin.py` — unfrozen, not custody-set, so a
   builder can land it): replace the single-name constant with the set of oracle modules
   declared by each milestone's law directory, resolved to expected paths, and abort if any
   `sys.modules` entry for those names resolves outside its frozen directory. This is a
   like-for-like widening of a check that already exists and already has a poison fixture.
2. **Extend `tests/poison/oracle-shadow/`** to carry a `_model` decoy as well — owner work at
   the sitting, since `tests/poison/` is author-key territory.
3. **The real fix stays queued and should now be scheduled**: package-qualified imports in the
   frozen law files, which needs the freeze protocol (new files + manifest rows, per CLAUDE.md's
   "do not edit a frozen law" rule).
4. **Consider sealing `tests/`** rather than only `tests/laws` and `tests/poison`. Every
   reproduction of this finding — and of RT-M1-01 before it — depends on `tests/` itself being
   writable without a manifest row. That is a `governance/tier-c.yaml` change: owner work.

## RT-M2-02 — Any law node can be retired to an expected failure by editing two builder-editable files, with every guard green. **High.**

**Claim.** The supersession mechanism went live for the first time in M2. Its registry, the code
that reads it, the code that validates it, and the only test that pins it are **all four in the
same unprotected tier**:

| File | manifest row | custody set | sealed dir | in `make verify` |
|---|---|---|---|---|
| `governance/laws.yaml` | **no** | **no** | no | data only |
| `conftest.py` | **no** | **no** | no | read at collection |
| `tests/test_law_validation.py` | **no** | **no** | no | via `pytest -q` |
| `scripts/check_laws.py` | **no** | **no** | no | **no** — not a gate step, not in CI, not in pre-commit |

Verified directly; `governance/laws.yaml`'s and `conftest.py`'s only appearances in
`MANIFEST.sha256` are inside the `#` notes block, which `parse_manifest` skips (`_gov.py:83`).
For contrast, the custody set does carry eight sibling scripts — `check_manifest.py`,
`check_concepts.py`, `check_decisions.py`, `check_receipts.py`, `check_tag_signers.py`,
`gen_custody.py`, `gen_projections.py`, `_gov.py`. **`check_laws.py` is the one that is missing.**

**The naive attack is blocked, as expected.** Adding a second `superseded:` entry fails
`test_law_validation.py:246` (`assert len(superseded) == 1`) and trips strict xfail on the
still-passing node. Two independent blockers — both living in unprotected files.

**Variant A — hiding a real regression (two files, no `conftest.py` edit).** The realistic
threat is not "retire a healthy law", it is *"my change broke a law, so I retire the law instead
of fixing my change"* — and then the node genuinely fails, so strict xfail is satisfied. A
one-word regression in `src/tannen/sources.py` (dropping `MissingRef` from `_cite`'s except
clause) breaks two L2.7 nodes. Cover-up: two registry entries plus a five-line relaxation of the
pin from `len(...) == 1` to a dict lookup — a diff that reads as ordinary maintenance. Result,
every gate step run individually:

```
check_manifest / check_concepts / check_decisions / check_tag_signers / check_receipts : OK
pytest -q            : 710 passed, 2 skipped, 3 xfailed
tannen laws report   : OK — 36 law(s) carry fresh passing evidence      [L2.7  ok  pass]
lint-imports         : Contracts: 3 kept, 0 broken
custodian.sh         : custody floor intact
```

D0139's recorded baseline is `712 passed, 2 skipped, 1 xfailed`. The attacked tree is
`710 / 2 / 3` — the same 715 items, two guarantees moved into the expected-to-fail column, and
**`tannen laws report` printing `L2.7 ok pass` over an implementation that violates L2.7.**

**Variant C — the shadow registry, and why the queued fix does not work.** Suppose the sitting
does exactly what **D0131 item (3)** proposes and puts `governance/laws.yaml` under the owner's
signature. It does not close the hole, because `conftest.py:24` is what *decides which file is
the registry*:

```python
SUPERSEDED_REGISTRY = ROOT / "governance" / "laws.yaml"
```

Extend that to also read a new `governance/laws.local.yaml` — `governance/` is not a sealed
directory, so a new file there carries no manifest obligation — and the attack runs with
`governance/laws.yaml` **byte-identical** (sha `78e85a8c…` in both sandbox and real tree) and the
pin test passing **unmodified**:

```
check_manifest: OK   ·   check_laws: OK — 1 superseded/pending node(s) name a live successor
tests/test_law_validation.py: 22 passed        <-- the pin, unedited, still green
tests/laws/m2/test_l2_inertness.py: 17 xpassed
```

**This is a correction to a remedy already queued for the sitting.** D0131 item (3) names
`governance/laws.yaml` and `scripts/check_laws.py`. Signing `laws.yaml` while `conftest.py`
stays unprotected is decorative.

**Two guards that should have caught it and structurally cannot.**

- **`check_laws.py::check_supersessions` validates existence, not relevance.** Verified:
  `_successor_exists` (line 199) only asks that *some* law file defines the successor id;
  `_record_exists` (line 210) only asks that *some* `decisions/*.yaml` contains
  `\nid: <record>\n`. Neither is tied to the retired node — so an entry retiring **L2.7** may
  cite successor **L2.4** and record **D0128** and pass. And the validator is not in the gate
  except as a subprocess launched from the very file an attacker edits.
- **`check_decisions.py::pytest_violation` rejects skips but says nothing about xfails.**
  Verified by reading lines 163-179: the branches are "does not collect", "skipped", "unexplained
  skip", and `returncode != 0`. An xfailed node exits 0, so a **binding pointing at a retired
  expected-failure reports green**. D0128 chose strict xfail specifically to dodge
  `ALLOWED_SKIP_REASON_PREFIXES` (RT-M1-05's fix); the dodge also dodged the binding check.

**Blast radius.** `conftest.py` marks on `item.nodeid.split("[", 1)[0]` — the *function* — so one
registry line silences every parametrisation of it (demonstrated: one line → 17 XPASS for L2.5;
one line → 7 for L1.9). Static enumeration gives **171 law functions across 36 law ids and 23
files**, collecting 507 items. The single real constraint is that retiring *all* of a law's nodes
leaves it with no evidence record, and `make verify` runs against a freshly-removed store, so the
law reads STALE and the gate goes red. Eight laws are single-node and therefore noisy to retire
(L0.1, L0.2, L0.6, L0.8, L2.4, L2.5, L2.6, L2.9). **The remaining 135 of 171 law functions (79%)
are silently retirable in one change.**

**Smallest honest fix.** The seam is *which bytes decide what is retired*, and today that is
three files, none protected, plus a validator that is neither protected nor in the gate.

Owner work at the sitting (each target is frozen and/or custody-set):

1. `governance/tier-c.yaml` → add **`conftest.py`**, **`scripts/check_laws.py`** and
   **`governance/laws.yaml`** to `custody.set`; regenerate and re-sign `custody.sha256`.
   **State the cost plainly:** putting `laws.yaml` under custody makes D0128's Session-B
   `pending`→`superseded` promotion an owner act, which is the one thing D0128 designed to be a
   builder two-line move. If that cost is unacceptable, drop `laws.yaml` and take (2) instead —
   but `conftest.py` and `check_laws.py` are non-negotiable either way.
2. Strengthen `check_supersessions` so an entry's `record` must be a **Tier-C, owner-signed**
   record whose bindings name the retired node, and the successor must be one that record names.
   This turns "a record exists" into "the owner signed *this* retirement", and preserves builder
   promotion: creating a retirement needs a signature, activating a signed one does not.
3. `Makefile` + CI → run `check_laws.py` as a first-class gate step (D0131 item 4, queued).
4. `check_decisions.py::pytest_violation` → treat an xfailed binding target as it treats a
   skipped one.

Builder-landable now, partial: manifest rows for `conftest.py` and `check_laws.py` — this
converts a silent one-line edit into a manifest diff that pre-commit rejects. It is **not** a
seal (RT-01: a row can be deleted with no trace) and does nothing for `governance/laws.yaml`.

**Explicitly do not** freeze or custody `tests/test_law_validation.py`: it changes every
milestone (D0129 and D0137 both rewrote it), and freezing it would halt Session B. Under (1)+(2)
its `len(superseded) == 1` pin becomes redundant — the signature, not the assertion, is the pin.

## RT-M2-03 — A citation to a real, resolvable source document can assert a row that document does not contain. **High.**

**Claim.** M2's headline promise is that a citation points at data that exists. It delivers
something weaker: `lineage` reports **structure**, not **authenticity**. `_cite`
(`src/tannen/sources.py:159-174`) classifies a stored value as `kind="source-row"` on a
four-clause conjunction — `isinstance(value, Mapping)`, `value.get("tannen") == SOURCE_ROW_TAG`,
`is_ref(origin)`, `isinstance(row, Mapping)`. Every clause is a shape test. `Store.put_value`
(`store.py:81-83`) is public and unguarded, and `Why.of` (`semiring.py:157-168`) validates atoms
against `REF_RE` — a regex — and nothing else. `Store.has` is defined (`store.py:106`) and is
never called anywhere in `src/`.

**Reproduction** (run against a `Store` in a temp directory; the worktree was not modified):

```python
real_doc  = b"id,verdict\n1,cleared\n"
real_src  = store.put_bytes(real_doc)
rel       = sources.ingest(store, real_src, ("id", "verdict"), [{"id": 1, "verdict": "cleared"}])

forged_ref = store.put_value({"tannen": "srcrow/1", "source": real_src,
                              "row": {"id": 1, "verdict": "GUILTY - per exhibit 7"}})
```

```
genuine: kind='source-row' source=sha256:8575089a... row={'verdict': 'cleared'}                store.has(source)=True
forged : kind='source-row' source=sha256:8575089a... row={'verdict': 'GUILTY - per exhibit 7'} store.has(source)=True

raw source document bytes: b'id,verdict\n1,cleared\n'
```

The forged citation names a source document that genuinely exists and genuinely resolves, and
asserts a row that document does not contain. Every field a caller can read matches the genuine
citation in type and validity.

**Why no store-side distinguisher can exist.** `ingest` writes its rows with
`store.put_value(source_row_value(source, row))` — precisely what the forgery does by hand:

```
source_row_value ref == hand-built ref ? True   (sha256:5ff3c4701288aec22...)
```

Content addressing makes the two byte-identical. There is nothing at rest to tell apart, so no
check reading the store can separate them even in principle.

**`ingest` verifies nothing about the source either.**

```
store.has(ghost) = False
ingest against a NEVER-STORED source succeeded; citation kind = source-row
```

**This falsifies a frozen spec sentence.** `docs/specs/m2.md:58` (frozen, `MANIFEST.sha256:75`)
reads: *"`ingest` is deterministic and reads bytes the store already holds."* It reads no bytes
and requires no such holding. `sources.py:22` states the accurate contract instead — *"reads
rows a caller already holds"* — so the code and its own spec disagree, and the frozen half is
the wrong one.

**No law would have caught it, and that is not an oversight in the laws.** No frozen M2 law
asserts authenticity; `test_l2_sources.py:58` asserts only the forward direction (ingest-minted
refs resolve), never the converse. L2.3/L2.4 are algebraic properties of `Why` and hold
identically over forged atoms. `grep -rn "srcrow\|source-row\|lineage" scripts/ governance/*.yaml`
returns **zero hits** — no guard reads these values at all. `make verify` therefore stays green
legitimately: nothing claimed what was broken.

**Exploitable by accident — and this is the likelier path.** The deliberate route needs a
hand-built dict. The accidental route is the sanctioned API: any caller who parses a document,
then normalises, filters or renames rows before calling `ingest(store, source_ref, schema, rows)`
mints citations asserting the source contains rows it does not. Ordinary ETL hygiene produces
false provenance with no warning.

**The obvious fix is wrong.** Adding `store.has(origin)` to `_cite` breaks the frozen laws:
all three M2 law files use `SOURCE = "sha256:" + "5e" * 32`
(`test_l2_sources.py:33`, `test_l2_lineage.py:26`, `test_l2_executor.py:31`), a fabricated ref
that is never stored. A `has` check is a false negative on lawfully ingested data.

**Proposed closure — admission plus a distinguishing kind, not a `has` check.**

1. `src/tannen/sources.py` — extend `CITATION_KINDS` so a citation whose row is not verifiably
   derived from its named source reports a distinct kind, and correct `ingest`'s prose contract.
2. A superseding law asserting the converse of L2.1: authenticity is either established or not
   claimed.
3. A decision record noting that `docs/specs/m2.md:58` is a frozen-spec defect, superseded
   forward per D0106 ruling 2 — never edited in place.

| File a fix touches | `MANIFEST.sha256` | custody set | editable |
|---|---|---|---|
| `src/tannen/sources.py` | not frozen (**zero `src/` rows in the manifest**) | no | yes |
| `docs/specs/m2.md` | **frozen** (row 75) | no | supersede forward |
| `tests/laws/m2/test_l2_{sources,lineage}.py` | **frozen** | no | supersede forward |

The implementation surface is entirely unfrozen, so the code fix is unobstructed; only the spec
sentence and the law files need the supersession route.

## RT-M2-04 — D0110's door is one component deep and single-shot, so §3's "any semiring carrying a `Why`" is false. **High.**

**Claim.** `why_slot` (`semiring.py:250-267`) returns **at most one** location — `"self"`, then
`"left"`, then `"right"`, returning on the first match — so `_refuse_unwitnessed`
(`rel.py:93-118`) inspects at most one `Why` component. Two bypasses follow, and the first needs
no nesting at all.

**Reproduction.** Every line below was run against the shipped package:

```
--- control: the door D0110 closed ---
CONTROL ZxWhy: refused (RelError)

--- depth-1 bypass: two Why components ---
product(Why, Why)     name=Why*Why     slot=left  -> ACCEPTED [({'a': 1}, ({{sha256:abab…}}, frozenset()))]

--- why_slot returns None ---
product(ZxWhy, B)     name=Z*Why*B     slot=None  -> ACCEPTED [({'a': 1}, ((3, frozenset()), True))]
product(Z, ZxWhy)     name=Z*Z*Why     slot=None  -> ACCEPTED [({'a': 1}, (5, (3, frozenset())))]
product(ZxWhy, ZxWhy) name=Z*Why*Z*Why slot=None  -> ACCEPTED [({'a': 1}, ((3, frozenset()), (3, frozenset())))]
```

`product(Why, Why)` is the sharper half: `why_slot` matches `.left` and returns, and the
right-hand `Why` is never looked at. The defect is not "depth ≥ 2"; it is **"at most one"**.

`Rel._validate_annotations` (`rel.py:59-75`) duck-types on
`("name","zero","one","add","mul","encode")` with no whitelist, so every semiring above is
admissible through the public API. The only toll is supplying an `annotations_reason` string.

**What the frozen spec claims.** `docs/specs/m2.md:97-100` (frozen, `MANIFEST.sha256:75`):

> `Rel` refuses an annotation that claims copies of a row it has no derivation for: nonzero in
> the count component, `Why.zero` in the `Why` component, **under any semiring carrying a
> `Why`**.

`product(ZxWhy, B)` carries a `Why`. It is not refused. And §3's consequence 2 —
*"the two maps part company only on `(n, ∅)`, which is now unconstructible"* (`m2.md:116`) — is
false: `(3, ∅)` is constructed above.

**The consequence, which is what makes this more than cosmetic.** `anti_join` computes
`slot = why_slot(S)` and attaches its absence witness only `if slot is not None`
(`ops.py:353-360`). With no slot, survivors carry no citation of the right relation:

```
--- CONTROL ZxWhy (slot='right')
   anti_join over R       -> []
   anti_join over R\{B}   -> [({'k': 1}, (1, {{sha256:c65acaeb…, sha256:aaaa…}}))]
   addr(R\{B})            = sha256:c65acaebe490ffdbe65…      <-- cited by the survivor

--- BYPASS product(ZxWhy, B) (slot=None)
   anti_join over R       -> []
   anti_join over R\{B}   -> [({'k': 1}, ((1, {{sha256:aaaa…}}), True))]
   addr(R\{B})            = sha256:898c02258aaa92ebd54…      <-- cited by nothing
```

The survivor is absent over `R` and present over `R \ D`, and its witness set is disjoint from
everything `D` touched. That is exactly the shape the deletion theorem's **iff** direction
exists to exclude.

**What this is NOT: the kill criterion did not fire.** §12 names *"a failure of L2.3 in the iff
direction"* as the stop-everything condition. L2.3 does not fail — it is exercised over the
shipped `ZxWhy`, where the witness is attached correctly, and it passes. `tests/laws/m2` is
green with every bypass above live (`12 passed`). What is false is the frozen **spec's**
universal claim about which semirings are covered, and the guarantee therefore does not extend
to semirings §3 says it does. Reporting this as a kill-criterion failure would be an overclaim;
reporting it as cosmetic would be an underclaim.

**Bounded by the store.** `Rel.from_value` refuses an unshipped semiring name — verified:
`RelError: semiring 'Z*Why*B' is not one this build ships; refusing to guess (§2)`. An
unwitnessed row therefore cannot be smuggled through the store or a trace. The exposure is
in-process: the public constructor, `_from_pairs`, and every operator's output.

**Law coverage — none.** The only `product(...)` constructions anywhere under `tests/` are
`test_l1_semiring.py:122` (`product(Z, Z)`, no `Why`) and `:128` (`product(Z, Why)` = `ZxWhy`
itself). The nearest law, `test_l2_sources.py:130`
`test_l2_2_a_semiring_with_no_why_component_is_untouched`, covers "no `Why`". Nothing covers
"a `Why` the locator failed to find" or "more than one `Why`".

**Exploitable by accident — yes, and the API invites it.** `semiring.py`'s own module docstring
says *"`Why` gives support-set provenance, and `product` composes them"*; frozen law
`test_l1_1_products_compose_generically` asserts that products compose generically; nothing in
the brief, specs, laws or docstrings says `Why` must sit at depth 1 or appear at most once. The
plausible user stories are ordinary: *"the default plus one more dimension"* →
`product(ZxWhy, B)`; *"join two provenance-carrying pipelines"* → `product(ZxWhy, ZxWhy)`. Both
silently lose D0110. The `annotations_reason` toll makes it worse rather than better: the user
writes a reason, believes they have performed the sanctioned §5.5 opt-down, and receives a
weaker guarantee than the spec promises, with no warning in either direction.

**Proposed closure.** The implementation surface is entirely unfrozen — `MANIFEST.sha256` has
**zero** `src/` rows and the custody set contains no `src/` path — so the code fix needs no
sitting.

1. `semiring.py` — add `why_slots(semiring)` returning **every** `Why` location by recursive
   descent; keep `why_slot` as the depth-1 accessor `_conjoin_witness` already uses.
2. `rel.py` — `_refuse_unwitnessed` refuses if **any** located `Why` is empty. Keep the function
   in `rel.py`: D0110 is owner-signed with an immutable `file: src/tannen/kernel/rel.py`
   binding, and moving it would break a signed binding.
3. `ops.py` — `anti_join` must not silently no-op. Either conjoin into every located slot, or
   **refuse by name** when more than one `Why` is present ("cannot decide which `Why` component
   attests this absence"), which matches the repo's refuse-never-coerce idiom and is the smaller
   change. Converting a silent unsoundness into an error is defensible.

The law and the spec need the freeze protocol: a **new** law file under `tests/laws/m2/` covering

## RT-M2-05 — Generated projections assert date- and custody-dependent facts that their input-hash structurally cannot cover. **High.**

**Provenance, stated plainly:** the core of this finding was identified during the planning
session that dispatched this pass, not by the pass. Probe E's mandate was to confirm it by
execution and push past it. Sections **N1-N8** are the new ground; the confirmation is R1-R3.

### The claim

`gen_decisions` (`gen_projections.py:113-145`) renders two things that are not functions of
`decisions/*.yaml`: the header line `Attention receipt: **FRESH** — …` and the per-record
`effective_status(rec, today, receipts_fresh)` column. The guard compares
`input_hash(sorted((root/"decisions").glob("*.yaml")))` against the header
(`check_decisions.py:336-341`). Neither `today`, nor `receipts/`, nor `allowed_signers`, nor the
git tag set is an input — and `make verify` never runs `make projections`. The only thing that
refreshes the file is the `regen-projections` pre-commit hook: builder-side, `--no-verify`-able,
never run by the gate.

### R1 — the guard prints the true state, then blesses the file contradicting it

`DECISIONS.md:10` in the same tree, same run: `Attention receipt: **FRESH** … fresh until

### R2 — it is wrong TODAY, not merely on 2026-09-08

The committed projection **understates three accepted decisions right now**, and

### R3 — a written promise nothing enforces

`decisions/0018-attention-receipts.yaml`, verbatim: *"While stale … check_decisions reports
BLOCKED, **DECISIONS.md and the digest show the accumulating blocks**, and CLAUDE.md's hard rule

### New ground

- **N1 — `CONCEPTS.md` is hash-complete (negative result).** `gen_concepts` takes no `today`,
  reads no receipts, runs no git, renders only record fields. Byte-identical across `--today`
  2020→2030. The blind spot is *not* present there. Its one unhashable assertion is the upstream
  commit pin, which is external by nature and handled out-of-gate by `check_drift.py` per D0028.
- **N2 — DECISIONS.md's input set is strictly weaker than the digest's, and the gap is
  file-shaped.** `gen_digest` deliberately includes `allowed_signers`, `receipts/*.md*` and
  `decisions/*.yaml.sig`, with a comment explaining why. `gen_decisions` includes none, yet
  renders `receipt_state`, which reads all of them. Deleting `receipts/2026-08-31.md.sig` flips
  line 10 to STALE with the hash unchanged. (`check_receipts` does catch that deletion, so this
  is not an escape hatch — but the guard that *owns* the projection cannot see a change in the
  very fact the projection asserts.) **Unlike `today`, these are files; there is no structural
  reason they are omitted.**
- **N3 — the git tag set is a non-file input.** `receipt_state` → `boundary_tag_dates` →
  `git tag -l`. Tags are refs; `input_hash` cannot cover them by construction. Demonstrated
  incidentally during this pass's own verification: a sandbox copy without `.git` rendered
  `fresh (no milestone boundary since)` instead of `fresh until 2026-09-07` — **same header
  hash**. A tagless checkout is not hypothetical; it is what `clone` without `--tags` produces
  (the RT-15/D0058 condition). Probe E also showed a later boundary tag rendering *"fresh until
  2026-10-07"* — a claim that the owner's attention is good for five more weeks, sourced from a
  git ref, in a file whose freshness guard is a hash over YAML.
- **N4 — `governance/policy.yaml.sig` is digest content but not digest input.** Deleting it
  flips the body line `Policy signature: present → absent` with the hash unchanged. **Downgrade
  from the hypothesis:** `check_manifest` now catches the deletion itself (`missing owner
  signature … (RT-04)`, EXIT=1), so this is a projection-completeness defect, not an exploit.
- **N5 — the digest's laws-evidence claim is driven by an environment variable.**
  `laws_section` → `build_report(root, None)` → `TANNEN_EVIDENCE_ROOT`. Same records, same hash,
  opposite claim: `M0 10/10 → 0/10`, `M1 17/17 → 0/17`, `M2 9/9 → 0/9`. RT-05's closure protects
  **`make verify`**, which clears its store; **`make digest` is a separate target that never
  does**.
- **N6 — and this changes how RT-07 must be closed.** The digest renders the previous digest's
  ratchet baseline, and `digest/*.md` is not in the digest's own input set: editing
  `digest/2026-08-31.md`'s metrics line changes the new digest's body with the hash unchanged.
  RT-07's filed closure is "verify digest header hashes the way CONCEPTS.md/DECISIONS.md are
  verified" — **that would not close this.** Any RT-07 fix must extend the input set as well as
  check the header.
- **N7 — `--today` grinds the spot-check sample.** `seed = input_hash[:16] ^ today`. Five
  consecutive dates give five disjoint K=3 draws. RT-11 names `tier`, `risk_flags` and K as
  builder-side levers on digest invisibility; **the generation date is a fourth it does not
  name**, and the cheapest, since it leaves every record untouched.
- **N8 — the sitting shows the owner a stale digest.** Verified against the committed
  `scripts/boundary_sitting.sh`: the owner-queue display is at **line 186**
  (`latest_digest=$(ls -1 digest/*.md | tail -1)`), and regeneration is at **lines 772 and 777**
  — after the sitting's decisions. So the "Requires owner" queue the owner reads at the top of a
  sitting was computed on an earlier day, and no guard has ever verified its header. Compose
  with N7: `tail -1` sorts lexically over `YYYY-MM-DD.md`, and that date is a builder-supplied
  CLI argument.

### Recommended fix — re-render, do not re-hash

Replace the header-hash comparison with a byte-for-byte re-render, and run projections inside
`make verify`:

```python
from gen_projections import gen_decisions
expected = gen_decisions(root, args.today)
if projection.read_text(encoding="utf-8") != expected:
    fail.add("DECISIONS.md is not what gen_projections would write today — run make projections")
```

*Against stamping the generation date into the header:* it answers "was this correct for the
date it claims?", not "is this true now?" — a file stamped 2026-08-31 and internally consistent
still passes on 2026-09-08 asserting FRESH. Closing that needs a second rule ("the stamp must be
today"), which lands on re-rendering anyway, having added a builder-supplied forgeable field
along the way. N7 shows exactly how such a field gets used.

*Against deleting the volatile content:* that satisfies the guard by discarding the feature.
The blocked-status column is what D0018 promised the owner. A guard made green by removing what
it guards is the failure mode `docs/proposals/2026-08-29-a-check-that-cannot-fail.md` exists to
name.

*For re-rendering:* it is complete by construction — `today`, `receipts/`, `allowed_signers` and
the tag set are all covered with no input list to maintain, and so is whatever volatile input
`gen_decisions` grows next. It also closes a gap the hash cannot reach today: the current check
verifies that the *header names the right record set*, not that the *body came from it*, so a
hand-edited row survives `make verify` untouched. And the false positive it introduces is the
correct alarm — a tree left untouched across a veto date goes red saying "run make projections",
which is precisely the state where the file asserts an expired custody claim.

**For the digest, a different shape** — a dated historical artifact *should* re-render
differently, so byte comparison is wrong there. Instead: verify digest headers at all (RT-07);
extend `extra_inputs` to `policy.yaml.sig` (N4), older `digest/*.md` (N6) and the evidence the
laws section reads (N5); and move `make digest` before the owner-queue display in the sitting
driver, selecting by explicit date rather than `ls | tail -1` (N8).

### Custody — every code change here is owner-only

`check_decisions.py`, `gen_projections.py`, `check_concepts.py`, `_gov.py`, `Makefile`,
`.pre-commit-config.yaml` and `boundary_sitting.sh` are all **custody-set**;
`governance/tier-c.yaml` is frozen *and* custody-set. A builder can file the record and draft
the patch, and nothing more. Note the irony worth recording: `DECISIONS.md`, `CONCEPTS.md` and
`digest/*.md` are in **neither** the manifest nor the custody set — and that is itself part of
the finding.

### D1 — Step 0's `RESUMED` test disables the precondition gate on *any* dirt. **Silent wrong answer.**

### D2 — Step 9's commit is optional and unchecked; step 10 tags unconditionally. **Corrupted artifact.**

Pre-existing, inherited from the M1 driver, and the highest-cost defect here:

```sh

echo "  governance/custody.sha256 sha256 = $(sha256sum governance/custody.sha256 | cut -d' ' -f1)"
```

So the project's **first owner-signed close tag** would quote hashes of bytes that are not in the
commit it points at — falsifying exactly the D0051 property ("authority-bearing tags quote the
delegation's hash alongside its text") those two lines exist to provide. Fix: require a clean
tree, or assert HEAD contains the sitting's changes, before step 10; and check
`commit_with_hook_retry`'s status.

## RT-M2-07 — Two M2 decision records overclaim what the code delivers. **Medium-high.**

Neither is an exploit. Both are records that assert more than the code does, which under BRIEF
§9 is its own kind of defect: the fold of the records is the truth, so a record that overclaims
is a false statement in the project's own memory.

### D0134 — "ingest writes nothing until the whole source is accepted": **OVERCLAIM**

The literal sentence is scoped and true: a refusal *in the first pass* leaves the store
byte-for-byte as it found it. Verified: a float in row 3 of 5 raises `CanonicalEncodingError`
with an empty store after.

What is not delivered is the record's stated *justification* — that the two-pass shape
eliminates uncited `srcrow/1` orphans, "the one failure mode an append-only store cannot clean
up after". It eliminates them for validation refusals only. A failure inside the write loop
(`sources.py:116-117`) reproduces the named failure mode exactly. Verified with a real,
unprivileged `EACCES` — row 3's fanout directory pre-created `0o500`, no monkeypatching:

```
[1] read-only fanout dir for row 3 of 5
    ingest RAISED: PermissionError -> [Errno 13] .../objects/e9/.tmp-u0aixv8i
    store after : 2 refs   ({'k': 0, 'x': 0}, {'k': 1, 'x': 10})
    D0134 claim 'leaves the store byte-for-byte as it found it': VIOLATED
    orphaned srcrow/1 values no Rel cites: 2
```

The brief's suggested lead was wrong and is recorded as such: `IntegrityError` at `store.py:96`
is in `get_bytes`, unreachable from `put_value`. The reachable mid-loop failures are all
filesystem-level.

**Mitigating, and the reason this is not high severity:** the residue is inert and self-healing.
No `Why` cites the orphans — the caller never received a `Rel` — so `lineage` never sees them,
and a retry of the same `ingest` is idempotent and absorbs them. The harm is bytes and
confusion, not incorrectness. That is the opposite polarity to D0126's real failure (a citation
to a document that does not exist). The record calls its own residue "D0126 read backwards" and
then treats it as equally fatal.

**Also weaker than advertised:** both pytest bindings are single-row or refuse-before-any-row.
Nothing in `tests/laws/m2/` exercises a multi-row failure inside the write loop. The record
diagnoses precisely this weakness *for the alternative it rejected* and then inherits it.

**Remedy: a new record, no code change.** A staging area buys nothing — N `os.replace` calls are
individually atomic but not atomic as a batch; true all-or-nothing needs a journal or a single
batch object, which is architecture, not a fix. The honest sentence:

> `ingest` is atomic with respect to **citations**, not with respect to **bytes**. If it
> returns, every atom of the returned relation resolves; if it raises, the caller holds no
> relation and therefore no dangling citation. An IO failure inside the write loop leaves the
> rows already written behind as uncited `srcrow/1` objects the append-only store cannot
> remove — inert, and absorbed by a retry.

### D0136 — "lineage classifies what it cannot resolve and raises on tampering": **OVERCLAIM on totality, FALSE on the fourth-kind premise**

**Two false statements, one of them in a frozen file.** Verified:

```
Why.of({"not-a-ref"})   REFUSED (SemiringError)
Why.encode(bad)         ACCEPTED -> [['not-a-ref']]
Rel(...)                ACCEPTED -> [({'a': 1}, (1, frozenset({frozenset({'not-a-ref'})})))]
to_value                ACCEPTED -> [[{'a': 1}, [1, [['not-a-ref']]]]]
content_address         ACCEPTED -> sha256:a8afcdeffb1538bdc60...
lineage                 RAISED tannen.kernel.refs.RefError
```

- `src/tannen/sources.py:57` — *"There is no fourth kind for a malformed atom because `Why.of`
  refuses a non-ref by name, so one cannot reach a `Rel`"*. It reaches a `Rel`.
- `docs/specs/m2.md:234` — the same premise, **frozen**.
- `src/tannen/sources.py:139-143` — *"**It is total** … never raised on"*. False for any `Why`
  not built through `Why.of`/`Why.decode`.

The asymmetry is exact: `_Why._check` (`semiring.py:170-173`) tests shape only; `Why.of` and
`Why.decode` are the only two gates; `_check`, `encode`, `add` and `mul` pass a non-ref through.
It bites on honest mistakes too — uppercase hex, a bare 64-hex digest with no `sha256:` prefix,
a `sha512:` atom. Per BRIEF §5, *"if the shortest spelling of a thing can violate a discipline,
the API is wrong, not the caller"*, and `frozenset({frozenset({ref})})` is the shortest spelling
of a `Why`.

**Contained:** `Rel.from_value` refuses it, because `Why.decode` calls `Why.of`. A poisoned
`rel/1` cannot be read back out of the store. The exposure is the in-process constructor.

**And the second binding is a check that cannot fail.**
`test_l2_7_an_atom_outside_the_pinned_grammar_is_unconstructible` asserts only that `Why.of`
raises; its docstring states the claim it does not test. D0136's own rationale cites D0114/D0116
— *"this repo has already paid once for a check that could not fail"* — while carrying one as
its evidence.

**Tampering is laundered into absence.** Verified:

```
control                            : source-row
after DELETING the stored object   : unresolved     <-- indistinguishable from 'never written'
```

Deletion, a rename, or a broken symlink all report a calm `"unresolved"`. `chmod 000` or
replacing the object with a directory raises `PermissionError` / `IsADirectoryError` — neither
classified nor `IntegrityError`. So the record's taxonomy ("can fail three ways") is missing at
least two, and the filename's *"raises on tampering"* is false: **verify-on-read detects
modification, never absence.**

**Remedy — a new record, plus one code change that is measured free.** Put the `is_ref` gate in
`_Why.encode`, not `_Why._check`: `_check` is on the hot path of every `add`/`mul`
(measured 4.2× regression on `Why.mul`), while `encode` is not (measured noise). And `encode`
is already the door the design has — `rel.py:85` reads
`semiring.encode(annotation)  # the annotation must have an image, or it is not one`. The door
exists and states the intent; `_Why.encode` simply fails to enforce the grammar behind it. With
the gate, `Rel`, `to_value` and `content_address` all refuse, which makes the frozen spec's §7
premise **true as written** — no fourth `kind`, no change to `sources.py`, no supersession of a
frozen file. Reported as run by the probe: 665 law nodes green with the gate applied.

Rejected: a fourth `kind="malformed"` (contradicts frozen §7 for no gain); catching `RefError`
in `_cite` (that is precisely the laundering D0136 correctly forbids).

The deletion-as-absence half is **not** closable this way — it is inherent to verify-on-read
over a content-addressed store and would need a separate manifest of what should exist. That
half is a narrowed claim only.

**Sibling finding, one layer down.** `src/tannen/laws/evidence.py:143` is
`except Exception as exc: yield ref, None, f"unreadable: {exc}"` — which *does* launder an
`IntegrityError` into a string, inside the evidence store, which is exactly what D0136 argues
must never happen.

**Freeze/custody:** `src/tannen/kernel/semiring.py`, `src/tannen/sources.py` and
`src/tannen/laws/evidence.py` are all unfrozen and uncustodied — a builder can land the gate.
The new record should carry `risk_flags: [ref-grammar]`.

# What this pass did not attempt, and where it fell short of its own rules

- **No probe touched** `tests/laws/`, `tests/poison/`, `governance/custody.sha256`,
  `allowed_signers`, or `scripts/custodian.sh` — out of scope by the brief, confirmed against
  `MANIFEST.sha256` and `governance/tier-c.yaml#frozen_paths` before each probe. Nothing was
  installed under `tests/poison/`: that is the owner's act at the sitting.
- **Nothing was closed.** Every finding above is reported, not fixed. Several fixes are
  builder-landable (`src/` is entirely unfrozen and uncustodied), and they are deliberately left
  for a session that is not also the session that found them, with the D0092 regression bindings
  written then.
- **`evidence/` was written to.** The pass was specified read-only against the worktree. One
  probe ran two M2 law files in the real tree before moving to a sandbox, appending three
  evidence records. `evidence/` is gitignored (`.gitignore:13`) and append-only by design, and
  `git status --porcelain` is empty at `d0c5e34` with no tracked file modified — but the rule was
  not fully kept, and saying so is cheaper than having it inferred from a timestamp later.
- **No signed artifact was forged or attempted** — no tag, no commit, no receipt, no Tier-C
  signature. Every M0 finding in that family was closed by a fixture at the M0 sitting, and
  re-attacking a closed fixture without a new hypothesis is not a fresh probe.
- **Two claims are reported as run-by-proxy, not re-executed by this author**: the 665-law-node
  green run validating the `_Why.encode` gate (RT-M2-07), and the full nine-step gate under
  RT-M2-02's variant A. Both were executed by their probes in sandbox copies with output quoted;
  the author independently reproduced the underlying exploits but not those full-suite runs,
  which cost 20+ minutes each. Everything else in this report was reproduced directly.
- **The blast-radius figure in RT-M2-02 (135 of 171) is arithmetic** over enumerated node counts,
  not 135 separately executed retirements.
- **Method deviation, stated for the record.** M0's and M1's passes were each run by a single
  fresh session. This pass was run by six subagents dispatched from the planning session, each a
  fresh context that never saw M2's implementation. That satisfies D0104's requirement but not
  its precedent. Two things compensate: the six probes were pre-registered, so coverage did not
  depend on any agent's curiosity; and every finding was re-verified by the dispatching author
  before entering this report, with one agent claim corrected and one false lead — issued by the
  author, not an agent — retracted mid-probe (see RT-M2-06). Whether the tradeoff was worth it
  is a judgement for the owner; the pass found one critical and five high findings, against M1's
  one critical and two high.
